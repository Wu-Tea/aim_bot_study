- 原图仅检出真实圆点：原图坐标 (176,120.5)，尺寸 10 px，分数约 0.914。长血条不输出 cue；移除圆点后 cue 数量为 0。
- 六种缩放的独立完整血条均被排除。原血条左端保留 4–32 px 的 29 个填充残段均被排除。

- 内部片段保持在原始位置：先输入两帧真实圆点和人工估计人框，再取消人框及圆点、仅保留片段。修复前 dev 基线与当前候选均续出 `cue_hold`，Y 从 199.5 变为 183.5（上移 16 px），没有 fire 权限。真实圆点仍在时，片段没有抢走跟踪。
- 将真实圆点的洋红像素移到与血条相连的位置，会使整个连通块超限，真实 cue 一起被拒；分离时正常。这是明确标注的合成粘连边界，不是原图故障。

104 组图像探针，外加四组 6 帧的选择器序列。原图正例、完整血条负例、合成残段、合成粘连分别记录在 `result.json`；不得把这份报告表述为“血条全面安全”或“实战已经复现误锁”。

## 当前防护与缺口

`CueDetector` 取完整 8 连通分量，即使分量超出搜索区域也会继续消费；拒绝边界裁断、4–18 px 以外、短长边比小于 0.65、填充比例异常及不符合周向分布/角落/质心要求的色块。因此完整长条不会被局部搜索切成小 cue。

生产 runtime 开启 cue identity 路径。该路径清除人物 ROI 的颜色质心和颜色加分，仅以独立形状检测与人物对应关系提供 cue 证据，避免长条的颜色质心绕过形状检查。

缺口在于小片段的像素形状也可能满足以上条件，且距离原 cue 足够近，因而通过后续时序对应。当前没有血条语义识别。盲目提高分数阈值会影响真实小圆点、菱形和 skull；后续修改需要真实残血/遮挡序列，并保留现有 cue 正例和性能边界。

## 复现

使用 Visual Studio C++ 工具链将本目录 CMake 工程配置到 `runs/bo7-cue-20261102/build` 并以 Release 构建。探针直接编译当前 `cue_identity.cpp`。选择器序列使用前一轮 `tests/november_acquisition_20261102` 构建出的 `replay_before.exe`（冻结 e039081）与 `replay_after.exe`（当前修复候选）。然后执行：

```powershell
python tests/bo7_cue_20261102/audit.py <用户原始PNG的绝对路径>
```

Python 需要 OpenCV、NumPy。人框 `[276,181,325,255]` 是在补边画布上人工估计的输入，置信度设为 0.9；没有重跑模型，也不发送真实游戏输入。生成的 `verified.png` 标注原图的圆点和被排除血条。
