# 产品需求文档（PRD）

## 1. 产品定义

SoundDirectionAssist 是本地运行的音频事件方向可视化工具，用于自有游戏开发、QA、离线研究、无障碍辅助和经授权演示。它不读取游戏状态，只分析操作系统公开音频接口提供的 PCM。

## 2. 目标用户

- 游戏/音频开发者：验证空间音频与 HRTF 输出；
- QA/研究人员：记录、回放和评估事件方向；
- 无障碍用户：在被授权的软件中获得粗方向视觉提示；
- 内容创作者：将方向事件显示到 OBS 场景。

## 3. 核心用户故事

- US-01：用户可选择一个有播放音频的进程，并确认只捕获其进程树音频。
- US-02：用户可加载本地、合法获得的目标声音配置或模型。
- US-03：检测到目标声音时，界面显示类别、粗方向和置信度。
- US-04：置信度不足、输入为 mono 或信息冲突时，系统显示 unknown 或不提示。
- US-05：用户可用 WAV 回放复现实验，不依赖目标程序实时运行。
- US-06：用户可导出不含原始音频的评估指标和诊断日志。

## 4. 范围

### 4.1 MVP 包含

- Windows 11 x64；
- 指定进程树的音频捕获；
- 系统混音回退模式；
- WAV replay、synthetic source；
- 内部 48 kHz stereo float32；
- 单目标事件类别；
- left/center/right/unknown；
- 独立外部显示层；
- 本地配置、日志、指标；
- CPU 推理的可选 ONNX 支持（后续里程碑）。

### 4.2 MVP 不包含

- 多个同时声源的独立定位；
- 精确连续角度、距离或高度；
- 游戏进程内插件、SDK、内存读取；
- 自动输入、游戏控制；
- 云推理、账号系统、遥测；
- 防截图、防录屏或隐藏 overlay；
- macOS/Linux；
- 模型训练 GUI。

## 5. 功能需求

| ID | 需求 | 优先级 | 验收摘要 |
|---|---|---:|---|
| FR-001 | 选择 PID 并捕获其进程树播放音频 | Must | 目标有音频时收到 PCM；无音频时状态明确 |
| FR-002 | 端点 loopback 回退 | Should | 可切换并标明是系统混音 |
| FR-003 | WAV replay source | Must | 同一文件多次运行输出一致 |
| FR-004 | Synthetic source | Must | 可生成已知 ILD/ITD 测试信号 |
| FR-005 | 统一内部 PCM | Must | 48 kHz、2ch、float32、interleaved |
| FR-006 | 事件检测接口 | Must | 输出类别、时间段、概率 |
| FR-007 | 方位估计接口 | Must | 输出 bin、可选角度、置信度、方法 |
| FR-008 | unknown/suppress | Must | 低置信度不强制方向 |
| FR-009 | 时间平滑/去抖 | Must | 事件不闪烁、不无限延长 |
| FR-010 | 独立 overlay | Must | 不注入；可锁定、缩放、透明度调整 |
| FR-011 | 诊断面板 | Should | 输入格式、帧率、overflow、延迟、状态 |
| FR-012 | 本地配置 | Must | 配置经 schema 校验；坏配置可恢复 |
| FR-013 | 离线评估 CLI | Must | 输出 detection/direction 指标和 JSON/CSV |
| FR-014 | 可选 OBS 输出 | Could | 独立里程碑，不阻塞 MVP |

## 6. 非功能需求

| ID | 需求 | 目标 |
|---|---|---|
| NFR-001 | 安全边界 | 无注入、无内存读取、无驱动、无反作弊功能 |
| NFR-002 | 隐私 | 默认不录原始音频、不联网、不遥测 |
| NFR-003 | 实时性 | 受控数据上事件 onset 到显示 p95 不高于 250 ms |
| NFR-004 | 稳定性 | 30 分钟运行无崩溃、无音频回调阻塞、overflow 可观测 |
| NFR-005 | 可测试性 | 核心算法可在无设备/无窗口环境测试 |
| NFR-006 | 可复现性 | 离线回放固定 seed/配置产生一致结果 |
| NFR-007 | 可维护性 | 模块单向依赖；公共 API 文档化；有 ADR |
| NFR-008 | 可访问性 | 提示不只依赖颜色；支持形状、文字和缩放 |
| NFR-009 | 许可证 | 发行依赖满足项目许可政策并生成第三方通知 |
| NFR-010 | 资源 | 基线常驻内存目标低于 250 MB；性能需在参考机记录 |

## 7. 指标与产品门槛

指标仅对已定义的受控数据集有效，不宣称跨游戏泛化：

- 检测 F1：目标 >= 0.85；
- left/right 符号准确率：目标 >= 0.90；
- 4-way top-1：目标 >= 0.75；
- 8-way top-1：研究目标 >= 0.60，未达标不得默认开启；
- 负样本误报：目标 <= 1 次/分钟；
- p95 端到端显示延迟：目标 <= 250 ms。

若 4/8 方位门槛未达到，产品降级为左右或“可能方向”提示，而不是放宽评估口径。

## 8. 状态机

`Idle -> SelectingSource -> Starting -> Capturing -> Detecting -> Degraded/Error -> Stopping -> Idle`

典型降级：

- mono 输入：检测可继续，方向 disabled；
- 模型缺失：确定性 baseline 或 detection disabled；
- process capture 不可用：提示用户切 endpoint fallback；
- 数据冲突/多个峰：输出 unknown；
- 目标进程退出：自动停止并保留诊断信息。

## 9. 发布原则

任何“更强准确率”不能以削弱安全边界为代价。若一个功能需要注入、内存读取、反作弊规避或未经授权素材，视为不属于本产品路线。
