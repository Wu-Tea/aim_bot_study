# 安全、隐私、公平性与合规约束

## 1. 允许的使用场景

- 自己开发或拥有源代码的游戏；
- 单机/离线研究；
- 经软件开发者、赛事或组织明确授权的测试；
- 无障碍辅助，但仍需遵守目标软件规则；
- 音频算法教学、QA、HRTF 可视化；
- OBS/录像中的观众信息展示。

## 2. 禁止的技术路径

- DLL 注入、远程线程、APC 注入；
- DirectX/OpenGL/Vulkan hook；
- 读写进程内存、扫描对象、解析游戏实体；
- 内核驱动、提权、句柄窃取；
- 反作弊检测、绕过、规避、隐匿；
- 网络包捕获/解密以获取游戏状态；
- 自动输入、宏、瞄准或决策；
- 防截图、防录屏或“只对玩家可见”的隐藏 overlay；
- 未经授权提取/分发游戏音频和模型训练素材。

这些限制必须存在于 `AGENTS.md`、代码 review checklist 和发布说明中。

## 3. 最小权限

- 默认以普通用户运行；
- 不安装服务或驱动；
- 不要求管理员权限；
- 仅请求捕获所需的 OS 音频能力；
- 不能捕获目标时给出错误，不尝试提权。

## 4. 数据处理

### 默认

- 音频只在内存中处理；
- 不保存原始音频；
- 不联网；
- 不遥测；
- 日志不记录用户名、窗口标题、命令行或完整路径，除非用户显式打开诊断。

### 显式录制模式

若未来加入录制：

- 用户必须主动启用；
- UI 持续显示录制状态；
- 可选自动删除策略；
- 文件包含来源和权利声明；
- 不自动上传；
- 默认目录和最大容量可配置。

## 5. 模型与样本供应链

- 模型文件必须有 SHA-256、来源、许可证和兼容的 feature config；
- 未知来源模型不可默认加载；
- 模型解析失败不能崩溃；
- 不支持自动下载或执行模型附带脚本；
- 仓库只提交自有合成测试音频；
- 发布物生成 SBOM/第三方通知是后续门禁。

## 6. 威胁模型

| 威胁 | 控制 |
|---|---|
| 恶意/损坏 WAV | 有界解析、长度检查、fuzz target、拒绝超大声明 |
| 恶意 ONNX | 文件大小上限、哈希、受信来源、异常捕获、CPU/线程限制 |
| 过量日志 | 轮转、大小上限、默认信息级别 |
| 缓冲积压 | 有界队列、drop 策略、监控延迟 |
| UI 欺骗 | 明确应用名称和状态；不模拟游戏 UI |
| 配置注入 | JSON schema、路径规范化、拒绝未知关键安全字段 |
| 目标进程变化 | PID/creation-time 校验；退出后停止，不自动附着未知新进程 |

## 7. 公平性提示

即使仅使用公开音频 API，第三方竞技软件仍可能禁止实时辅助可视化。产品应：

- 首次启动显示授权使用声明；
- 文档强调用户负责遵守目标软件规则；
- 不提供“兼容反作弊”“不被检测”等宣传或功能；
- 对明确不允许的环境建议关闭，不提供绕过方法。

## 8. 安全验收

发布前必须确认：

- 二进制导入表和代码中无注入/hook/驱动能力；
- 无 `OpenProcess` 读取权限路径，除非仅用于最小公开元数据且经审查；
- 无防捕获 API；
- 无出站网络请求；
- 原始音频默认不落盘；
- 依赖许可证与哈希记录齐全；
- 错误日志已做隐私检查。
