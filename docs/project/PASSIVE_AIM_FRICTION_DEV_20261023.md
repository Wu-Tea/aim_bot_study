## 当前实现

- 只在 canonical 手柄、AssistActivation::Off、连接正常且没有 ADS/手动开火/触摸开火时运行。Primed、Engaged、Application 和鼠标/legacy 均不进入该分支。
- 复用最近的 selector 快照，不开启 AI，不请求新检测。需要当前可靠敌人身份、有效身体几何，以及置信度至少 0.5 的所选非友军 person，或 selector 已配对的当前 cue_hold。未配对 cue 不建身体参考。
- 身体矩形内部生效，半宽/半高最多 60/90 px。逐轴只减弱朝向身体中心的现有手动输入；边缘、中心平滑归零，朝外立即原样输出。另一轴不继承减速，不产生主动拉动，也不改变身体参考或索敌身份。
- 最大减速 **8%**。45% 以下保持完整的空间减速曲线，45%–75% 推杆平滑退出；任一轴达到 75% 时整个手动向量原样通过。零输入仍为零。
- 不保留旧目标减速状态，不增加时序门槛、锁或分配。只扫描已有候选中的所选目标，最多 32 项；大幅推杆和不合格快照提前返回。
- 图像时效采用 min(32 ms, 原观测过期设置)，空帧/不可靠目标立即恢复；现有输出发送前的过期撤权机制现在也覆盖没有 AI target 的被动减速。诊断模式为 `passive_target_friction`。
- Vision keepwarm 配置/频率没有改动，当前日志 profile 为 keepwarm=true。关闭闲时检测时，没有新鲜观测就不会产生减速；这项功能不私自唤醒检测。

生产修改位于 `native/controller_native/passive_aim_friction.h`、`native_gamepad_controller.cpp/.h`。此前任务的 AimDynamicsShaper 改动仍保留。用户明确授权了 Off 状态原始透传的局部例外，AGENTS.md 已记录，未改变已触发辅助时的手动权限曲线。

## 验证方法与结果

`tests/passive_friction_20261023/` 直接链接前后两个原生控制库。基线库及对应头文件在开始改动前保留到 `runs/passive-friction-20261023/baseline/`，避免新旧类布局混用。复用 `tests/hipfire_flick_20261023/fixtures/` 的 8 段、1,358 个去重日志样本，原始来源和提取过程见上一轮报告。

8 段 × 5 种输入状态 × 4 种相机条件 = **160 个日志场景**：原状态、强制未触发辅助、95% 大幅转身、循环 Off/轻按 ADS/完全 ADS/开火/Application、始终 ADS。每种状态 49,488 tick。相机条件为固定观测，以及 900/1400/2200 px/(stick·s)、6/12/24 ms 延迟的三个近似闭环。

| 检查 | 结果 |
|---|---|
| 95% 转身 | 所有相机条件输出/误差不变；固定观测 12,372 tick 完全一致 |
| 持续 ADS | 所有相机条件输出/误差不变；固定观测 12,372 tick 完全一致 |
| 获取/身份覆盖 | 160 个场景首个获取 tick、拥有目标 tick 数全部一致 |
| 原状态回放 | 平均误差变化 −0.0791～+0.0151 px |
| 状态循环 | 平均误差变化 −0.1962～+0.1183 px，无减速进入激活状态 |
| 全程强制 Off | 平均误差变化 −0.1170～+4.4650 px，不能声称所有手动轨迹更准 |

原日志中先经历被动减速、随后按 ADS/开火，固定观测对照有 222 个激活 tick 的输出变化，最大单轴 **0.001760**。这些 tick 的被动减速均为关闭；前面不同的实际输出仍进入交付历史和后续运动估计。持续 ADS 完全一致，所以不能将此写成 ADS 被直接乘减速，但也不能宣称跨状态历史下输出绝对相同。

另加 **27 个定点刹停场景**：4/8/16 ms 观测间隔、三种响应/延迟、40%/65%/95% 推杆。固定手势 112 ms 后松杆，原设定会越过目标约 5%。40% 推杆的 9 个场景，最终绝对偏差全部减小：

| 响应 / 延迟 | 原版最终偏差 | 8% 版本（随图像间隔变化） |
|---|---:|---:|
| 900 / 6 ms | 越过 1.688 px | 提前停 0.997–1.099 px |
| 1400 / 12 ms | 越过 2.625 px | 越过 0.102–0.420 px |
| 2200 / 24 ms | 越过 4.126 px | 越过 2.990–3.700 px |

95% 转身完全一致。部分 65% 高速场景跨过减速区域太快而没有作用；没有为此提高检测频率或延长旧框寿命。曾试 12% 上限，低响应场景提前停 2.62 px，绝对偏差反而超过基线 1.69 px，因此最终减到 8%。12% 中间结果保存在 `comparison-12percent.json`，不是当前版本。

两独立种子 231023/981027，128 个 2/20 秒场景，**每版 1,408,128 tick**。覆盖方向变化、对角输入、目标切换/空帧和状态循环，物理输出、8% 限幅、不反向、大幅透传、来源点不变检查通过；首个获取/拥有目标 tick 数无变化。随机 Off 压力场景最差均值 +3.3585 px；状态循环最差 +0.9445 px。这些是固定手势与简化相机下的数值差异，不是游戏胜率或实际玩家操作变化。

最终 Release 构建成功，**CTest 51/51、Base 482/482**，包括既有鼠标测试。新增 40,000 次随机逐轴边界检查和实际 NativeGamepadController 生命周期/输出过期测试。旧 `manual_axis_motion_simulation` 将“所有松 ADS 后必须精确透传”的断言更新为用户此次允许的局部 8% 减速边界；其他状态仍检查原始透传，没有删除输出/过期/来源点检查。

## 复跑与边界

从仓库根目录，用 Visual Studio bundled CMake 配置 `tests/passive_friction_20261023` 到 `runs/passive-friction-20261023/build`，Release 构建使用 `/m:1 /nr:false`。`friction_before.exe` / `friction_after.exe` 参数依次为：profile、fixture 目录、输出目录、种子；种子 0 跑日志和刹停，231023/981027 跑随机场景。当前 profile 快照为 `runs/hipfire-flick-20261023/profile-used.toml`，没有修改用户配置。

三轮输出分别放 `before-0..2` / `after-0..2`，随机输出放 `random-before/after-<seed>`；执行 `python tests/passive_friction_20261023/compare.py` 生成 `runs/passive-friction-20261023/comparison.json`。详细逐 tick 数据在对应 `trace.csv`；CTests 在 `ctest-final.txt`。

拟真没有游戏图像、FOV、世界运动真值，也没有真实人的反馈反应。强制 Off 是反事实输入，不是录像原样重现；目标可见性/切换时刻来自固定日志，不能验证真实相机变化后 Vision 是否仍选中相同目标。轻微减速改变手动行程，适合帮助刹停，不是自动跟枪或保证所有换目标动作零影响。最终手感仍需 dev 实机试用，clean 未同步。
