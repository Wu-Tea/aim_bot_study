## 当前行为

- 在完整捕获框内独立检测黄色/红色小标记。COD 圆点和死敌骷髅均作为有效 cue 候选；使用原离线实验的颜色、大小和形状筛选，不区分两类标记的语义。血条和大菱形通过形状/大小筛选排除，但这不等于任意场景下的可靠语义分类。
- cue 决定初次索敌和持续身份，默认选择拾取半径内最靠近准星的 cue，有明确索敌方向时保留方向偏好。另一人体框更靠近准星、置信度更高、重复出现或重排，均不能自行更换 cue 身份。
- person 只关联已锁 cue 并提供当前身体/胸部几何。沿用现有身体置信度、几何规则和胸部位置配置；新 cue 尚未关联人体时只有内部身份，没有瞄准点和控制权限。
- cue 有歧义或缺失时不发布旧坐标。视觉身份记忆最多保留 50 ms，过期后允许重新索敌。独立 cue 匹配沿用离线实验的颜色/大小、42 px 局部步长、36 px 预测残差和候选分差。
- 有新鲜 cue 但 person 暂时缺失时，复用已有 cue_hold：只保持瞄准权限，不开火；人体几何的 180 ms 上限不延长。过期后持续可见的 cue 仍可持有身份，直到人体重新提供几何。
- 正常手动修正不参与换人，显式 HandoverTarget 可以交接，同一手势 ID 只消费一次。持续手动退出、松手透传和下游 32/40 ms 边界保持原逻辑。
- 本轮启用点为手柄 RuntimeLoop。鼠标入口和旧 person 选择策略调用者保持原有语义。

## 验证

- dev 全部原生 Release 目标构建完成；启动器使用 `native/build/Release/cod_native_runtime.exe`。
- CTest 51/51 通过。新增 7 项 Vision 回归后 BaseVisionSelection 56/56；随后补充 cue→适配器→原生控制器完整链用例，BaseEndToEnd 50/50。
- 独立 cue 匹配随机验证：4 个种子，每种子 32 个短/长场景，2 秒和 20 秒、60 Hz，共 168,960 帧。种子为 2026101902、32452937、49979807、104395489。目标做平滑运动，竞争 cue 与目标相距 70 px，顺序随机；这不覆盖所有交叉、重叠、快速镜头运动或图像误识别。
- 像素到 selector 回归覆盖另一个目标靠近准星、人体漏检/重复/重排、无人体的初始 cue、180 ms 几何期限、50 ms cue 失踪、时间倒退/重复、缺失/不完整帧、手动修正与主动交接、黄色/红色/RGB/BGRA/坐标原点。
- 完整链用例覆盖：只有 cue 时不能通过下游原始人体候选偷偷取得权限；人体关联后进入 ADS；漏检不改变下游目标身份；cue_hold 不开火；持续手动退出；零死区原始输入透传。
- 9 段现有录像共 5,435 帧使用当前原生 TensorRT 和 dev selector 回放。879 帧有目标输出，其中 684 帧直接关联人体、195 帧 cue_hold；这是输出覆盖计数，不是准确率。所有空目标帧无瞄准/开火权限，cue_hold 无开火权限。
- 用户确认的死敌标记 v2-f631 和 v3-f150 都进入生产独立检测器的候选。v3-f150 自动关联到死敌标记；v2-f631 自动先锁到更靠近准星的红色枪口效果，未输出人体目标。不能将“标记纳入候选”写成“自动索敌准确”。

## 已知限制与试用

彩色纹理、装备和枪口效果仍可能被误识别为 cue。误锁后可能暂时不跟真正的人；若它同时误关联到人体，也可能跟错人。本轮解决的是 cue/person 的身份职责和试用接入，未证明比旧版总体识别更准，也未证明用户录像中的原始两目标往返现象已得到完整复现和实机修复。
