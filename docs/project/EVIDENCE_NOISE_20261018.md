# 3% 过滤职责修复：候选验证与未完成的发布条件

2026-10-18。生产实现冻结于 DEV `f9f42d3`；clean 候选 `1cb9a12` 位于 `codex/evidence-noise-20261018`。**实际 clean 仍为 `86b34ea`，没有合入候选。** 小修正被吞的根因已移除，数值约束和聚焦闭环通过；相邻高速弱证据移动组明显退步，因此不能宣称整体行为验证通过。

## 根因与职责

旧实现对整形后的 AI 输出逐轴应用 3% 硬死区。该位置只知道幅值，不知道输出来自真实位置残差、维持目标运动，还是测量噪声。前轮轨迹的 800 个 tick 中，源偏差约 (1.59,-2.28) px，solver 请求约 (0.0201,0.0286)，最终却全为零；ADS 也因此长期不能真正到点。

新 `CaptureEvidenceFilter` 在 capture 证据层工作：用实际交付历史和相机响应把短历史对齐到当前相机坐标，在当前 capture 时刻评估局部线性位置拟合。观测扰动在相应空间尺度内连续减弱，超出噪声模型的新测量保留主导。固定偏差与匀速轨迹没有幅值死区，也不被整体缩小。

- 保留 `gamepad.assist.input_deadzone` 的旧键名、范围和 0.03 数值，界面改为 **AI 观测降噪**；尺度为配置比例 × 相机响应 × capture 间隔，单位为像素。它不再表示“杆量小于 3% 一律归零”。
- 控制测量偏移独立存储；源胸部点、身份和原始时间戳不改。ADS 的测量速度偏移与位置偏移一致；BodyLock 仍使用原来的相机补偿位移累计和 slew，不将真实低速运动按信噪比压向零。
- 保留已有 25 ms 运动历史尺度，最初样本直接通过；不增加排队、固定等待、完成延时或产品开关。局部线性拟合对匀速信号没有固定时间偏移；加速、形变及错误相机模型仍可能产生估计误差。
- 最低追赶参考、曲线、权限权重、手动仲裁、输出力限、独立压枪及热更键保持。最终输出不再因幅值小而清零，也没有补最低输出。
- 原 capture 最多 32 ms 可缺帧预测；超过 32 ms、未到 40 ms 只保留身份/未完成 ADS，缺帧辅助瞄准和开火权为零；40 ms 释放。过滤历史不续期。

## 结果：必要小修正能收敛，降噪没有被关闭

已知相机响应、包含噪声的开发组后段均值误差（px）：

| 场景 | 旧版 | 候选 |
|---|---:|---:|
| 居中，±0.35 px 观测噪声 | 0.091 | 0.234 |
| 小偏差收敛 | 1.547 | 0.037 |
| 慢速二维移动 | 1.332 | 0.126 |
| 开火/固定压枪 | 1.706 | 1.170 |
| 远点获取后交接 | 1.405 | 0.004 |

独立种子的结果方向相同。四种子居中组原始测量 RMS 0.286 px，经生产链位置过滤后为 0.262 px，证明降噪确实发生；实际中心误差 RMS 约 0.251 px，99.75% 的后段 tick 在 0.5 px 内。旧硬死区在这个纯噪声场景下更安静，候选没有保留其全部静默效果，不能说所有噪声场景都改善。

仅在夹具中将降噪设为 0 的消融显示：随机居中组后段误差从无过滤的 2.523 降至 2.296 px；但已知相机组从 0.230 至 0.234 px，慢速压力组也有部分代价。观测噪声减小不等于每种闭环的最终误差都减小；发布参数没有设为 0。

模型不匹配的独立随机组后段均值：居中 3.356→2.608 px、小偏差 4.063→3.914、慢移 4.447→3.819、开火/遮挡 11.537→11.237。每个案例保留在 `results.json`，不只选改善案例。

## 未满足的条件：高速弱证据交接后退步

前轮高速移动场景按证据强弱拆分，四种子后段均值：

| 移动组 | 旧版 | 候选 | 解释 |
|---|---:|---:|---|
| 明确敌人证据，32 例 | 1.557 px | 1.505 px | 整体接近，个别例有退步 |
| 弱证据，32 例 | 15.721 px | 21.976 px | ADS 更早正常完成后，较低的 BodyLock 权重与预算成为约束 |

具体反例为开发种子 2026101841、case 8、2 秒：后段误差 4.708→28.041 px。160 ms 时旧版请求 (-0.0102,0.0256) 被清零，仍停在 ADS；到 800 ms 旧版依然是 authority=1 的 ADS，输出 X≈-0.0938。候选已正常到点并交给 BodyLock，400 ms 起可见 authority=0.0736，800 ms 输出 X≈-0.0343，随后积累跟随误差。

该场景开镜后真实响应为 1956×0.76=1486.56 px/(stick·s)，目标 X 速度幅度为 140 px/s，单纯维持峰值移动就需要约 0.0942 的杆量，超过既有弱证据 0.0736 的权限预算。实际输出还受原来的权限权重、二维预算与位置响应约束，不能把全部差异都归结为硬饱和。**确认的传播路径是：小修正不再被吞 → ADS 较早正确完成 → 更早受原有弱证据 BodyLock 限制 → 高速移动误差增加。** 并非新的降噪等待，也不是 32/40 ms 被放宽。

旧版因无法完成而长期保留 ADS 权限不能当作正确交接基准，但退步同样不能隐藏。恢复末端死区、延迟交接或提高 BodyLock 权限均不符合本次要求。探索中的总速度信噪比缩放也已撤去，因为它会削弱真实慢移。

因此尚未满足“行为验证通过后合回 clean”的条件。候选已可审阅/复验，实际 clean 不更新。是否接受这类弱证据高速移动作为发布边界，需要用户明确确认；否则继续在 DEV 讨论整体交接目标与既有权限的可实现范围，不能自行把退步判为通过。

## 使用与保真边界

复跑方式、全部输入和统计区间见 [夹具说明](../../tests/evidence_noise_20261018/README.md)。新旧主结果为 `results.json`，旧场景全量对照为 `legacy-results.json`，逐 tick 反例位于 `legacy-diagnostic-before/trace-2026101841-8.csv` 与 `legacy-diagnostic-dev/trace-2026101841-8.csv`，两端一致性在 `parity.json`。

相机、框噪声、后坐力与开镜过程是合成模型，FIFO 交付和浮点杆量也不等于真实设备的 latest-only 观测和量化输出。所有仿真结果均不代表实机验收。个人模型、配置、日志未覆盖；实际 clean 的启动入口仍运行上一版。
