# 监听期间 mouse_start 无法启动：对照检查

用户确认入口：`scripts/launch/mouse_start.bat`。

用户采样：`runs/mouse_input_monitor/111216-198686437`。30 秒记录 13484 个事件，无缓冲丢弃或读取错误；Hook 11413 条，Raw Input 2071 条；两条流均持续到约 29.698 秒。Hook 包含 26 次左键按下、26 次左键抬起。该记录没有应用启动结果，也不能证明点击已送达某个窗口，不能据此单独判断应用启动失败原因。

## 实验和证据

先在未修改的运行程序上做直接启动 A/B，再在补充日志后的用户实际 BAT 入口上重复。监听窗口已创建、且监听进程在比较过程中保持存活。均只进行无捕获注册检查；默认驱动预检失败后，才重现该默认配置的启动失败。

| 检查 | 监听关闭 | 监听开启 |
| --- | --- | --- |
| 默认 Interception `--check-transport` | 退出 2，DLL/驱动接口不可用 | 同左 |
| 显式 Win32 `--check-transport` | 退出 0，Hook/Raw Input/F11/F12 注册与释放成功 | 同左 |
| 默认正常启动 | 退出 1，设备不可用/不明确或热键注册失败的组合错误 | 同左 |

完整记录：

- 直接运行：`runs/mouse_input_monitor/startup-ab-1788831164562027900/summary.json`
- 实际入口：`runs/mouse_input_monitor/launcher-ab-1788831400908662000/summary.json`
- DLL 与接口分层探针：实际入口目录下 `dll-probe.json`

DLL 探针实际结果：文件存在，SHA-256 与固定上游版本一致；DLL 加载成功，8 个必需导出函数齐全，但 `interception_create_context()` 返回空。系统驱动枚举没有匹配的 Interception mouse/keyboard 服务。因此不应继续将“缺 DLL”和“驱动接口不可用”混为同一个已确认原因；本次已排除 DLL 缺失或导出缺失。

本机默认启动失败可在没有监听器时独立重现。注册检查未复现监听并发冲突。更早的失败位置在 Interception 接口建立，而不是 AI、Vision 或控制参数。没有将这个结果推广为“任何环境下监听都不可能干扰其他应用”。默认路径仍被驱动条件阻塞，尚未恢复可运行的完整鼠标链路。

## 本次修复范围

启动器原先直接退出，双击运行时错误窗口随之关闭，也不保留日志。新增 `scripts/launch/mouse_native_logged_start.ps1`，由原 BAT 调用：实时显示标准输出和错误，写入唯一命名的 UTF-8 日志，保留运行程序退出码。运行程序失败时 BAT 停留，便于读取错误。自动测试可设置 `MOUSE_START_NO_PAUSE=1`。原参数转发和默认 transport 保持原意。

这是启动诊断修复，不是驱动修复或监听兼容性修复。未安装驱动、未启用输入拦截、未修改控制器源码或重建运行程序。

行为回归测试以无效参数触发捕获前失败：修改前因没有持久化日志而失败，修改后日志包含原错误和 `exit_code=1`。全部 `tests.test_startup_scripts` 21 项通过。实际 BAT A/B 又验证了参数转发、成功退出 0 和失败退出 1/2，以及监听并发时相同的结果。
