2026-10-20，用户根据两段实机录像否定上一版 cue 必需策略，提出 person / cue 使用 OR，并在创建目标时记录两者位置。用户进一步明确：同一个 cue 持续可靠时，允许超过 180 ms 继续使用已记录的 cue→胸部偏移。本轮在 dev 实现并构建，供后续实机试用。未修改 clean、个人模型/配置/Profile，也没有修改工作区已有的 ADS 控制算法。

## 当前行为

1. **独立 person 可以取得和维持目标。** 沿用原置信度、几何、拾取范围、确认流程和胸部计算。独立 cue 可为其关联人体提供已有的标记证据，但 cue 缺失不会否决同一目标的可信 person。
2. **同一帧的可信 person 与唯一匹配 cue 建立参考。** 记录该帧身体框、胸部/瞄准区域、cue 坐标和目标 generation。若初次仅 person，后续出现有效配对时也能建立参考；只有 cue 且从未见过配对人体时，不凭空生成身体位置。
3. **person 漏检时使用当前 cue 平移参考。** 当前胸部 = 参考胸部 +（当前 cue − 参考 cue）。身体与瞄准区域同步平移；不递归积分，不用弱框或 cue 推导结果重新训练偏移。相同 cue 连续可靠时不再受 180 ms 身体几何期限限制。可信人体重新出现时按当前人体定位，并以新的同帧配对校正参考。
4. **身份与有效观测仍分开。** cue 缺失或匹配歧义的当帧不输出旧 cue 坐标；原 50 ms cue 匹配记忆仅用于短暂重关联，过期清除身体参考。主动换目标、reset 清除旧参考。可信 person 仍可独立输出；正常手动修正不参与换人，显式交接沿用原 person 生命周期。
5. **cue 延续只提供瞄准权限。** 下游当前帧 32 ms 控制 / 40 ms 身份时效、持续手动退出、逐轴权限与零死区透传保持原规则。圆点、死敌骷髅仍属于独立颜色候选；没有新增按标记语义区分的开关。

实现主要在 `native/vision_native/src/target_selector_fusion.cpp`；原 person 路径继续供未启用融合的调用者使用，手柄 RuntimeLoop 启用新路径。没有调整模型权重、Profile 或 ADS 力度。
