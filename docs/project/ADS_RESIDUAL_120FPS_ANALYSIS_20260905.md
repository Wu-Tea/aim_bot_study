# ADS 复测：120 fps 视频、开镜前 200 ms 与剩余制动缺陷

2026-09-05。视频：`E:\newnew\Replay 2026-09-05 16-37-44.mp4`，重点为约 7、9、11 秒。用户反馈 BodyLock 已明显改善，ADS 仍抖动。

**结论：确认并修正了上一轮未覆盖的 ADS 接近中心制动缺陷。** 旧代码在位置请求达到约 0.12 时，把反向的误差速度前瞻全部削掉；目标明明正在快速接近中心，控制器却仍可能按静止目标的力度推动。先越过中心，再反向纠正，随后再次越界，形成横向摆荡。上一轮处理的是零点附近的请求突跳，两者是不同的缺陷。

**根因、传播路径与修复层级**

生产数据路径为：同一目标的新鲜源瞄准点 → `TargetCoordinator` 计算屏幕误差速度 → `AdsAcquisitionController` 将其作为停止前瞻 → `ResponseModelAimSolver` 限制位置与速度合成 → DynamicsShaper → 手动权限处理 → 开火 / 压枪合成 → 交付。

位置项近似为 `p = error / (arrival_horizon × response)`；ADS 速度项为 `m = error_rate / response × (12 ms / arrival_horizon)`。Y 方向的到达时间还保留现有方向系数。这里的 12 ms 是当前停止前瞻配置，不是本次新加的延迟。

旧反向限制是 `|m_allowed| <= |p| × (1 - smoothstep(|p| / 0.12))`。当 `|p| >= 0.12`，右侧变为零，反向前瞻被完全抹掉；接近该边界时也几乎被抹掉。它原本约束持续跟随的反向运动项，却错误地限制了 ADS 用于停止的误差前瞻。第一次被破坏的不变量由共享求解器拥有：**ADS 已预测即将过零时，必须允许前瞻降低当前定位需求。**

本轮只在 `motion_is_error_rate_lookahead` 为真且位置 / 速度反向时，改为 `|m_allowed| <= |p|`。因此保留完整制动力，最多把该轴减到零，不能提前预测穿过源位置并反向请求。上一轮零点连续性处理继续保留；BodyLock 的持续运动项仍走原有规则。没有增加等待窗口、全局降力度或新配置参数。

现场 15 个未开火样本使用相邻源时间戳重建速度，调用实际生产 ADS 求解器拟合未直接记录的响应信念，旧请求向量重建误差均小于约 1.2×10⁻⁵。这支持该机制与现场输入相符，但拟合值仍是内部响应信念推断，不是独立测得的游戏响应。开火后的速度另有观测约束，未用未过滤的误差差分冒充开火后的实际输入。

**纵向、时延与仍未解决的证据空缺**

三例的物理 RT 采样均为零，但日志存在自动开火及最终 fire 输出；“没有手动扣 RT”不等于“没有开火”。9、11 秒的有效开火阶段会合成约 −0.2 的 Y 压枪输出。例如 11 秒约 +83 ms，整形 Y 约 +0.0051，最终 Y 约 −0.1949；开火停止后该附加项消失。135 ms 附近还涉及已有手动权限阶段的变化。因此 Y 的阶跃需要沿最终输出链解释，不能全部归为视觉误差或 ADS 算法反向。

源画面 present 到计划决策的延迟中位数分别为 11.37、10.46、11.52 ms，最大值约 14.36、13.67、13.67 ms。再叠加整形、输出和未标定的游戏响应，旧方向仍可能在画面过零后短暂持续。12 ms 停止前瞻与这些量同一数量级，但不能简单相减得到端到端余量。代码中的响应学习延迟配置也不是实测执行延迟。

本轮没有依据不完整的实机闭环数据改动压枪、AutoFire、FOV 模型或全局增益。剩余验收重点是：新版是否仍出现第一次横向过冲；若横向已稳而纵向仍跳，需要分别匹配自动开火状态和真实右摇杆输入，再建立独立回归。不能用此次求解器通过测试来宣称这些链路已完成实机验收。
