# BodyLock 7.36%：预算与需求增益的职责分析

用户已明确拒绝接受弱证据移动退步，也不允许合回clean。本轮只分析和运行外置探针，生产控制器未改，实际clean仍为`86b34ea`。

## 结论与前轮纠正

7.36%是现有策略算出的视觉权限值，并被实现为物理输出预算；它不是物理测量出的必然上限，也不是已校准的敌人概率。当前实现还把同一个值用作位置和持续运动需求的乘数。**既有预算确实可能不足，但预算内的运动需求也被过度削弱；前轮把退步主要解释成权限不足、转而请用户接受边界，结论不完整。**

不是`a²`意义上的连续两次乘法。求解器执行的是先`a×需求`，再约束到`a`对应的力限。第二步不一定触发，第一步却每次都会减小合法需求。这两种职责混在同一个字段里，破坏了“已到点且所需速度在预算内，应能维持到点”的条件。

## 7.36%如何产生

复现夹具设置检测可靠度0.92、颜色已检查、没有当前敌人cue、同代身份也从未确认敌人，目标距离处于70 px以内。`TargetCoordinator`选择`unconfirmed_enemy_near_authority_scale=0.08`，因此`a=0.92×0.08=0.0736`。

这是仿真输入对应的具体值，不能当作所有实机BodyLock的固定常数。BodyLock保守敌人证据策略有历史产品依据，但本次检查没有找到0.08恰好是最优物理限制的标定依据。检测置信度和“允许施加多少杆量”也不是天然同一单位。

| 环节 | 当前职责/行为 | 是否又乘一次7.36% |
|---|---|---|
| coordinator | 可靠度×敌方证据系数生成视觉权限，ADS准入后为1，BodyLock按证据取值 | 产生该值 |
| BodyLock入口 | `min(aim_authority,reliability)`，同时把有效目标速度声明为总维持速度 | 没有平方；本例仍为0.0736 |
| solver需求合成 | `(位置需求+受约束运动需求)×authority` | **在这里缩小整项需求** |
| 曲线反变换及最终椭圆 | `max_axis=min(Profile力限, authority×adapter预算比例)` | 是限幅，不是再乘一次 |
| gamepad整形 | 原slew与交接处理；默认不是mouse定时ramp | 没有普遍的7.36%乘法 |
| 最终手动仲裁 | 按轴处理真实手动意图，保留15–30%权重、反向/退出/开火保护 | 无手动时不再缩小本例请求 |

代码依据：`target_coordinator.h:48`、`target_coordinator.cpp:914`、`bodylock_follow_controller.cpp:40`与`:63`、`response_model_aim_solver.cpp:166`与`:177`、`assist_control_state_machine.cpp:102`与`:241`。`min`和相同边界的重复投影不应误报成重复增益。

历史显示需求乘数早于最终预算；2026-08-12增加了曲线反变换后的预算保护，原因是弱证据大请求不能越界，但保留了原需求增益。现有测试覆盖大请求不能越界，却没有覆盖“预算内的已知目标速度在零位置误差处应能完整维持”。

## 生产求解器反例：无需加权限也有明显损失

条件：无手动、位置误差0、线性相机响应1000 px/(stick·s)、已知目标速度60 px/s、a=0.0736、最低追赶参考仍0.5。

1. 维持目标居中需要`60/1000=0.06`杆量，低于0.0736预算。
2. BodyLock把该速度标记为有效的总目标运动，`motion_weight=1`。
3. solver再次乘身份权限，输出`0.06×0.0736=0.004416`。
4. 实际只能抵消4.416 px/s；最终限幅没有触发，生产BodyLock与无手动仲裁输出也为0.004416。

因此目标必然先离开中心，位置误差逐步积累，靠位置反馈补回被缩小的维持速度。这个有残差的平衡违背了本轮“停在点上”的目标。最低追赶不能解决：零位置误差时位置项应为零，不该借位置最低值补目标运动的错误缩放。

探针的理想60 px/s闭环、20秒后段平均误差：当前公式70.192 px；只取消运动项重复缩放、保留位置增益和原预算为0.0024 px；全部需求只受原预算约束则接近数值零。峰值输出分别为0.0600、0.06174、0.0736，均不越原预算。**这只是机制反事实，不是完成全链修复。**

真正超预算的100 px/s场景，即使移除需求增益仍只能输出0.0736，残差继续增长。非线性曲线下必须比较`相机响应×forward_curve(预算)`，不能直接把杆量百分比当线性速度；探针也覆盖此项。

## 回到上轮实际全链退步轨迹

开发种子2026101841、case8、2秒，候选轨迹400–1399 ms的1000个BodyLock tick：

- 仅21个请求达到99.9%以上的预算；平均使用预算49.25%。
- 最终输出与请求的最大二维差约0.000690，绝大部分损失发生在请求生成，不能归责为手动仲裁普遍二次衰减。
- 500 ms请求X约-0.011956，观察到的目标维持需求约-0.052405；它在总需求合成时被压至约-0.003857。该时刻不是最终预算把输出剪小。
- 目标峰值确实需要约0.0942杆量，超过0.0736；这一硬边界仍成立，但不能解释其余大量未用满预算的跟随损失。

旧3%死区令ADS延迟完成，是暴露问题的触发条件；缺陷所属是BodyLock总运动需求与权限消费契约，不是ADS完成时机、手动意图或32/40 ms时效。

## 同一设计还存在的职责风险

生产coordinator探针确认：同一身份、同样0.92可靠度、相同敌人证据，从69.9到70.1 px，authority由0.0736跳到0.2208。距离同时改变需求和权限，能形成“偏得更远反而获得三倍预算”的控制变化。该分支有“近处应当能看到敌人cue”的历史策略动机，不能仅凭跳变就自动取消；但必须独立审查，不能把它当成固定物理限制。本轮未修改它。

此外，停车余量按完整目标运动定义相机剩余工作，BodyLock消费者随后又缩小总目标运动，两处对“维持速度”的含义不一致。应统一可实现总运动需求、已交付工作和最终约束的坐标/职责，而不是添加一个新的速度最低值。

## 可行方案，尚未实施

推荐保留现有视觉预算、Profile力限、手动仲裁与原capture的32/40 ms边界，先修预算内需求的职责：

1. **证据是否可信**由身份、观测时效和运动估计负责。运动估计有效不等于敌人身份强证据；弱身份仍受原预算约束，不能借运动绕开它。噪声处理不能简单把真实目标速度往零缩，也不能把任意瞬时框速度当作确定运动。
2. **需要做多少运动**由生产求解器负责。已确认总目标速度用于维持移动，位置项只消除剩余偏差，刹车扣除已交付工作。至少应消除已确认总目标速度被身份权重再次缩小的路径。
3. **允许输出多少**由原有最终二维物理包络负责。保持0.0736及其他当前预算值，不除以authority补增益、不加最低输出、不绕过曲线或手动保护。实际输出可能更多地使用原本闲置的合法预算，这是修正错误需求，不是增加允许的力限；仍须检查误跟噪声的代价。
4. **位置增益是否也应移除这份权重**单独验证。仅修运动项影响较小，但保留位置权重仍让有效响应时间随敌人证据改变；“全部只用预算”职责更统一，却影响更大。两者都不能未经噪声、手动、开火和阶段交接验证就直接采用。
5. **阶段交接**继续按真实完成条件发生，不等待BodyLock能跟上才结束ADS。保持目标、相机、运动估计和已交付状态连续；可实现范围内应无额外需求塌陷，超出原预算仍明确限幅。

实施前的回归应先锁定“零误差、有效恒速、需求在预算内、无手动”反例，再覆盖静止噪声/错误速度、二维斜向预算、两种曲线、人工反向与逐轴释放、开火、ADS→BodyLock、缺帧与32/40 ms。然后才做独立种子全链短长比较。不能把本探针的理想闭环当成这些验证已经完成。
