# 跟踪补充检查与录像轨迹测试集

用户要求继续检查跟踪算法，并从录像提取移动轨迹加入拟真。本轮完成轨迹素材与运行入口，新增速度估计反例、双目标交叉诊断和 ADS/cue 交接诊断。生产代码、Profile、模型和 clean 均未修改。

## 已接入的轨迹

`tests/vision_controller_study_20261020/trajectories/` 保存 **17 条 / 2,645 帧**，包括：

- 两段主录像各 3 条屏幕运动：横向位移、折返、纵向变化。
- person→长 cue、混合来源、漏检、短目标、重新取得目标。

每条同时提供 CSV、完整原生 `.records`、来源元数据。CSV 包含时间、原视频帧、selector generation、分段编号、位置、身体大小、来源、置信度、运动锚点和测量速度；缺帧不补位置、不跨身份计算速度。导出器逐字段验证，除 capture 时间原点外，原生数据保持不变。

这些是**屏幕测量轨迹**，不是世界坐标真值；包含原玩家转视角和检测误差。特别标为 `diagnostic_fault` 的轨迹用于检查系统如何面对错误证据，不能当成真实人物的理想移动轨迹进行调参。分段身份也不是人工确认的人物真值。

## 新发现一：单帧速度限幅会把往返抖动变成单向运动

**已确认的估计器缺陷，P2。** 根因在 `native/controller_native/bodylock_target_motion_observer.cpp`：先将每次导数归一化后限制到 ±1.25，再以间隔为权重积分最近 25 ms。不同间隔产生不同导数，只有较快的一侧触发限幅后，位移不再抵消。

固定目标的测量扰动例：

| 输入 | 真正净位移 | 当前稳态估计 | 只解除内部样本限幅的诊断对照 |
|---|---:|---:|---:|
| 8 ms 内 +5 px，17 ms 内 −5 px | 0 | 约 0 px/s | 约 0 px/s |
| 8 ms 内 +20 px，17 ms 内 −20 px | 0 | **−240 px/s** | 约 0 px/s |
| 8 ms 内 −20 px，17 ms 内 +20 px | 0 | **+240 px/s** | 约 0 px/s |
| 两侧各 12.5 ms，±20 px | 0 | 0 px/s | 0 px/s |

相机响应假设 1400 px/s/归一化响应，没有相机工作。第二行原始导数 +2500 / −1176.47 px/s；正侧被限制为 1750，8 ms 只留下 +14 px，而负侧仍为 −20 px，得到 −6/0.025 = −240 px/s。这里的保护改变了估计方向/均值，不只是限制输出强度。

4 个种子、2/20 秒共 **256 个**不同幅度/响应/间隔案例，180 个有超过 50 px/s 的零净位移估计偏差。这个比例来自刻意覆盖触发条件的压力集，不是游戏发生率。诊断对照的最大残余约 0.000227 px/s。对照只更改独立观察器对象的内部样本上限，生产库没有打补丁，也不意味着应上线取消所有限幅。

### 实录测量也可触发方向反转

已加入 `dev_cue_jitter`。dev 视频 170.941667、170.958333、170.966667 秒，帧 20514、20516、20517，同代 cue 的 Y 为：

`276.666687 → 298.666687 → 274.666687`

净位移 −2 px / 25 ms，即 **−80 px/s**。将这组实际测量间隔和位移输入生产观察器，在零相机工作、响应 1400 的隔离假设下，输出为 **+296.667 px/s**，方向相反。该数字不是录像当时实际 Controller 的世界速度估计；它证明录像中的测量形状足以触发同一数学问题。

建议在估计层保持净位移一致性，分清异常证据处理和最终需求/物理输出约束。应保留输出上限，并覆盖变帧率、短漏检和两轴往返噪声；避免再用额外延迟压住漂移。

## 新发现二：cue 已到准星，ADS 仍可能等 person 返回才完成

**行为已复现，属于与长 cue 策略需要一起审视的完成条件。** 固定相同目标和几何，先用 person 建立 ADS；200 ms 时胸部到达中心并保持不动：

- 持续 person：216 ms 完成 ADS，转入 BodyLock。
- 200–1600 ms 使用新鲜同代 cue：到 1592 ms 仍为 `AdsAcquire / AcquiringManualSafe`，权限 1，完成时间为空；1600 ms person 返回后，在 1616 ms 完成。

`target_coordinator.cpp` 中 `settled_frames_` 和 `center_cross` 均排除 `cue_continuation_candidate`。`ads_lifecycle_reducer.cpp` 在延长时间耗尽后进入手动安全追踪，时间不会自动证明完成，因此不会自行转 BodyLock。后者符合既定的“不能靠超时制造成功”，问题应从允许何种新鲜证据证明到达来讨论。

新 Vision 允许可靠 cue 长时间延续，完成判断仍只接受人体。由此会让持续 cue 跟随继续运行 ADS 算法，未按到达状态交给 BodyLock。这里没有把模式停留直接说成已经证明的甩枪/过冲：中心静止反例可以保持零输出，但生命周期和后续控制策略不同。若允许 cue 证明到达，仍须独立保留无开火和身份/时效边界。

这也解释了上一轮 clean 121.5 秒窗口为什么许多中性仿真持续保持 ADS；不能简单把原因归结为检测噪声。

## 新发现三：近乎重叠的双目标交叉可能串身份

**合成真值测试确认的身份局限，尚未证明录像中具体哪次跳变属于此问题。** 先只出现 A 并取得它，再加入同尺寸/置信度的 B，以相反方向匀速交叉。测试仅提供人体框；没有提供可区分的外观、cue 或真实人物 ID。真值标签只供测试统计。

4 个种子 × 60/120 Hz × 4 种垂直间距，共 32 组：

| 两框垂直间距 | 发生 A→B 串换 / 组数 |
|---|---:|
| 0 px | 8 / 8 |
| 2 px | 2 / 8 |
| 8 px | 0 / 8 |
| 20 px | 0 / 8 |

全部 10 次串换都继续保留原 selector generation，没有发出换代。代表案例：60 Hz、速度 171 px/s，A 在第 22 帧位于 X=342.7，B 位于 X=337.3，selector 由 A 转向 B，却保持 generation=1、changed=false。

原因在 `target_selector.cpp::select_multi_candidate`：可匹配的多个候选按离上一帧胸部点的距离挑选 active match，缺少运动预测或对应关系证据；交叉后另一人可能更接近旧位置。`boxes_match/targets_match` 又把这个近邻算成原身份。

人体框完全重叠且没有其他可区分证据时，任何方法都无法保证真实身份；这里的改进方向应是明确歧义、利用已知运动/外观/cue 证据恢复对应，而不是给未知身份继续宣称确定锁定。需要保留普通近邻取得与主动 handover 性能，不能用统一等待掩盖。
