# 手柄视觉辅助桌面应用：GUI 功能与交互需求

用途：将本文单独交给一个没有项目历史、没有见过现有界面的设计 agent，让其独立设计应用首页和主要功能页面。本文提供产品事实与验收条件，不规定现有配色、布局、圆角、图标或组件库。设计者可以重新组织导航，但必须让下述功能与状态可达。

## 1. 这是什么应用，谁会用它

这是 Windows 桌面工具。用户选择本地识别模型，应用采集游戏画面并识别目标，再由原生程序将辅助修正与用户的手柄输入共同处理。GUI 负责配置、调参、可视化解释、启动停止以及查看运行反馈。模型推理和手柄控制在独立的原生进程中运行。

用户通常知道“跟随太慢”“到点摆动”“抓取范围太大”等感受，但未必理解配置字段或控制算法。他需要看懂一个参数影响什么、改动是否保存、运行中的程序是否已采用修改。不能让用户通过猜测按钮是否响应来判断启动是否成功。

一份配置是一个独立工作方案，包含模型与设备设置、辅助参数和响应曲线。用户可以按任何场景自由命名、创建、复制和管理配置，不受固定游戏列表限制。新配置需要明确选择模型后才能运行。

关键术语：

| 术语 | 面向用户的意义 |
| --- | --- |
| 首次瞄准 / ADS | 用户开镜后，将准星向选定目标点移动的初始阶段 |
| 持续跟随 / BodyLock | 持续纠正准星与目标点之间的位置偏差 |
| 输出上限 | AI 在一个轴上最多使用多少摇杆行程；100% 为满行程 |
| 响应时间 | 修正的快慢，单位毫秒，与输出上限是不同参数 |
| 输入死区 | 小到指定程度的 AI 辅助输入不输出；不应暗示它改变了用户原始摇杆输入 |
| 响应曲线 | 摇杆输入与响应的映射，可用控制点编辑 |
| 热加载 | 保存参数，并请求正在运行的程序采用这些修改；部分设置需要重启 |
| 范围预览 | 帮助理解参数的交互示例，不是真实画面，也不是实时控制输出 |

## 2. 用户最重要的三件事

1. **开始使用**：创建或选中配置 → 选择模型 → 确认设备和输入尺寸 → 点击一次启动 → 看清正在检查、正在启动、等待手柄、运行或失败。
2. **边用边调**：确定想改变的手感 → 找到相关参数 → 通过说明和预览理解效果 → 修改 → 保存并应用 → 知道是否成功生效。
3. **保留方案并比较**：复制配置或曲线 → 修改副本 → 切换回来时草稿仍在 → 导入、导出或删除不造成无声的数据丢失。

首页需要首先支持这些任务，而不是展示一组与当前操作无关的统计卡片。设计者自行决定首页是调参工作区、运行准备页还是其他结构，并解释这个选择适合哪类用户、如何通向另两类任务。

## 3. 全局工作空间

无论进入哪个功能页面，用户应能知道：当前配置名称、是否存在未保存修改、当前运行的配置及其状态，以及下一步可执行的主要操作。

必备能力：

- 选择当前配置，切换页面或配置时保留各自草稿。
- 启动、停止、保存、保存并应用、在必要时重启。
- 未选模型时提供直接选模型的入口；正在运行其他配置时，切换并启动需要说明将停止哪个实例。
- 将“配置已保存”“运行程序已采用”“需要重启”作为不同结果表达。
- 关闭窗口时，如果存在未保存修改，提供清楚的处理选择；关闭 GUI 不意味着停止已经运行的原生程序。
- 失败信息能够看到、能够采取下一步行动，例如重新选择模型或查看日志。不能只闪一下后消失。
- Ctrl+S 保存并应用；菜单、对话框和说明均支持键盘，关闭后恢复合理的焦点。

不强制把所有操作做成常驻按钮，但启动、停止和保存应用不应埋在很深的位置。

## 4. 功能区域与内容

现有功能可分为以下五个区域。名称和导航形式允许重设计，能力不能遗漏。

### 4.1 参数调校

这里是最频繁使用的工作区。按用户的调节目的组织参数，避免几十个字段连续堆放。

| 参数主题 | 常用内容 | 次级内容与解释需求 |
| --- | --- | --- |
| 首次瞄准 | 横向、纵向输出上限；响应时间；基础抓取半径 | 开镜触发条件、启动阶段细节；解释范围与实际目标点的关系 |
| 持续跟随 | 横向、纵向输出上限；横向、纵向响应时间 | 跟随范围与近点行为；不能把“框内”解释成已经到达瞄准点 |
| 输入与手动 | AI 输入死区、手动与辅助的关系 | 响应学习、手动介入以及手动输出补偿；补偿是有内部参数的设置组 |
| 目标与识别 | 目标高度比例、姿态相关选点、友方过滤 | 与目标点和识别框的关系；让用户区分抓取范围与跟随范围 |
| 开火与压枪 | 压枪开关及输出、腰射保留比例、手动/自动开火按键、开镜后禁火时间 | 次级开火条件与参数说明 |

字段规则：

- 输出比例统一用百分比，时间用 ms，画面距离用 px；同类含义不得一处显示 0–1、另一处显示百分比而不解释。
- 数字可精确输入；有滑块的字段，滑块与数字表示同一个值。
- 范围与校验明确。输入 0 必须按字段定义得到 0 的行为，不允许隐藏最低值；非法值不能静默改成另一个值。
- 真正启用/禁用某项能力才使用开关。展开参数组应有清楚的展开入口和状态。
- 有说明的字段可以提供说明入口，点击后必须出现实际内容；没有说明就不要提供空入口。
- 次级设置展开后保持主页面的字体、间距、对齐和层次；收起后回收空间。

### 4.2 范围与输出示例

这是参数调校的辅助解释工具，可以作为同页区域、可收起的辅助视图或其他形式；不应为了放大示例图而让常用参数被迫滚出视口。

必须能展示：准星中心、识别框、实际目标点、当前范围，以及当前示例位置的横向/纵向输出。必须标注它采用静止目标和线性响应的简化假设，不是游戏中的实时输出。

交互包括：拖动目标；到点、近距、中距、边界的位置示例；改变目标高度、姿态和水平/垂直偏差。首次瞄准与持续跟随使用对应模式；在目标设置场景中可切换预览阶段。拖动过程中不能因为自动缩放而让目标位置含义不断变化。

### 4.3 响应曲线

用户需要看到映射曲线，并通过拖动或精确数字编辑控制点。提供插入、删除、撤销、重做、预设选择、自定义曲线保存，以及 JSON 导入导出。

起点和终点固定为 0% 与 100%，控制点必须严格递增。精确数值编辑需有明确的应用动作；尚未应用的点位输入不能在保存配置时被悄悄忽略，切页也不能丢失。错误应靠近正在编辑的位置。

曲线导入失败要说明原因；导出取消不应显示成功。次级菜单、预设选择和文件操作也属于完整设计的一部分。

### 4.4 配置管理

提供自由创建、选用、复制、重命名、删除、导入、导出、恢复初始参数和编辑完整配置的能力。

列表至少能区分名称、曲线类型、是否选中、是否运行、是否存在未保存草稿，以及是否已选择模型。没有配置时要有明确的创建入口。名称很长、配置很多、配置文件损坏都需要可用的展示。

运行中的配置不能直接删除；删除需确认并保留可恢复备份。外部文件已变化时不能用旧草稿直接覆盖，应提示重新载入。完整配置编辑面向高级用户，提交前需校验；普通用户不应被迫接触配置文本。

### 4.5 模型与设备、运行反馈

模型与设备：选择本地 TensorRT `.engine` 文件，显示文件名和实际输入尺寸；尺寸来自模型读取，不能由文件名猜测。模型与配置尺寸不一致时，说明将修改哪些值并确认同步。提供采集宽高、工作/空闲检测帧率、输入设备选择与刷新，以及诊断记录设置。选模型、同步尺寸、保存、启动要形成完整流程。

运行反馈：展示实际运行阶段、实体手柄连接情况、虚拟输出连接情况；展示应用平均 FPS、开镜期间平均 FPS、近 5 秒开镜 FPS。没有有效采样时显示缺失状态，不能用虚构数字填充。可查看日志、控制 Fusion 调试显示，并查看/导出响应学习数据。响应学习包含跟随和首次瞄准的普通区、减速区，显示当前响应、学习响应、置信度与样本数。

## 5. 状态与异常设计

至少设计以下状态，而不仅是“已有一个完整配置、正在运行”的理想画面：

| 状态 | 用户应明确知道的事 |
| --- | --- |
| 新安装、没有配置 | 从哪里创建，创建需要什么 |
| 配置未选模型 | 还缺什么，如何继续 |
| 点击启动后的检查阶段 | 点击已被接受，不需要重复点击 |
| 原生程序初始化中 | 仍在启动，尚未宣布运行成功 |
| 等待手柄 | 程序已准备到哪一步，缺少哪个连接 |
| 运行中，有草稿修改 | 正在用的参数和未保存修改不是同一回事 |
| 保存成功，但需要重启 | 数据已保存，运行效果尚未完全更新 |
| 模型损坏、配置不合法、启动失败 | 原因、当前保留状态和恢复入口 |
| 精确曲线点位尚未应用 | 如何应用或放弃，不得无声丢弃 |
| 请求处理中或快速连点 | 一个操作只提交一次，显示持续进度，完成/失败后允许继续 |

## 6. 布局、视觉和操作质量

视觉方向由设计者提出。希望它有成熟桌面应用的辨识度、清楚的视觉优先级，并让图形与控件承担实际解释作用。不能只靠大段文字说明工作流，也不应为了装饰添加无功能图表和指标。

窗口可以缩放。以桌面窗口内的真实内容区验收，需要覆盖约 1344×901、1500×801 和 824×601；不要只检查宽高同比缩放。Windows 标题栏、系统缩放、提示条都可能改变剩余空间。

默认常用任务应能合理放下；长列表和高级设置允许局部滚动。出现滚动条时不能突然压窄整个布局。展开/收起后应恢复空间。次级菜单的文字、图标、焦点和选中态必须与主页面一致；分隔线使用统一规则，不能无意间只缺一个单元格。

基础可访问性包括文字对比度、清楚的焦点、键盘操作、可理解的按钮名称，以及不依赖颜色区分状态。动效应服务于状态理解，尊重系统减少动效设置。点击关键操作后，应在下一次界面绘制时提供可见反馈；耗时操作不能冻结页面。

## 7. 请设计 agent 交付什么

1. 信息架构与首页选择：先说明用户打开应用最先看到什么、为什么，以及如何进入其他任务。
2. 可交互的静态原型：覆盖首页、调参、曲线、配置管理、模型设备和运行反馈。允许重组页面，但所有功能可达。
3. 至少演示一次完整流程：新建配置 → 选择模型 → 启动 → 改参数 → 保存应用 → 需要重启时的处理。
4. 把说明浮层、展开参数、更多菜单、文件操作反馈、确认对话框、错误态和空态做完整，不能只有主页面好看。
5. 展示宽矮窗口和小窗口的适配。模拟数据明确标注，静态原型不要声称已连接真实模型或设备。
6. 简短说明视觉取舍：哪些元素体现产品特点，哪些是通用组件，以及怎样避免套用通用管理后台。

评审重点是功能理解、操作闭环、层级、次级页面完成度和适配能力。截图漂亮只能证明静态表现，不能代替交互验收。

## 可直接交给设计 agent 的任务

请仅依据本文，为这款 Windows 手柄视觉辅助应用独立设计 GUI。你没有现有 UI 截图，也不需要沿用既有布局。先提出信息架构和首页逻辑，再实现可以点击体验的 HTML 原型。保留所有必要功能与异常状态，特别检查子菜单、参数展开、启动反馈、配置 CRUD 和小窗口布局。视觉风格由你提出并说明理由，优先形成完整、可操作、有辨识度的桌面产品。
