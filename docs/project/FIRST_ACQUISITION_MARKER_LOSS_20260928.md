# 第一段录像：标记消失导致人物观测被否决

历史快照：本报告记录第一轮 marker-loss 修复及当时的验证结果。随后用户明确“尸体可瞄、不能锁住用户”，最终规则和编译交付见 [可见区域选靶与尸体可瞄规则](VISIBLE_SELECTION_CONTRACT_20260928.md)。日常程序现已编译替换；下文旧尸体拒绝策略和测试仅描述第一轮状态，不代表当前产品要求。尚无实机 A/B 验收，此结论不包含另外三段录像的全部问题。

## 原因与证据

第一段 `Replay 2026-09-28 15-40-01.mp4`，约 10 秒的门口目标。日志中 ADS epoch 3 在等待 220.9937 ms 后以 `no_target` 消耗首发机会，615.9939 ms 后才接入目标。日志没有逐候选拒绝理由，不能仅凭 `candidate_count` 断言目标已识别。

使用 SHA-256 与实机相同的 `best_480x384.engine` 对原视频中央 640×512 区域重新推理，并运行原生选择器后，补齐了拒绝链：

1. 人物曾获得黄色敌方标记，形成带标记历史的身份。
2. 黄色标记短暂消失，`enemy_marker_loss_grace_expired` 在最近标记间隔超过 50 ms 时置 `active_marker_expired_`。
3. `candidate_matches_expired_marker_region` 把旧位置附近、当前未带标记的人物框直接过滤。这里用的是约 108 px 的跟踪半径，不要求证明人物已经死亡。
4. 空候选分支持续保留这一否决状态；后来的清晰人物观测不能自行解除它。Controller 因此拿不到目标，首发等待最终耗尽。

原生诊断回放在视频 frame 1155 进入该状态。frame 1170–1206（9.750–10.050 s）共 37 帧，旧版选择数 **0/37**，修改后 **37/37**。清除历史后持续处理相同输入的对照组也能选中该人物。视频随后显示同一门口人物及黄色生命条，支持“活人被历史标记否决”的解释。

限制：录制视频是压缩后的 120 FPS 图像，非原始 DXGI 帧；回放不含用户右杆意图。视频与日志的人工对齐约 ±200 ms。这里证明的是可复现的选择器缺陷，不能把回放某一帧冒充实机某个 Controller tick。

## 修复边界

修改 owner 为 `VisionTargetSelector`：删除“历史敌方标记过期 → 附近人物永久否决”的状态与分支。标记时效继续限制仅凭颜色进行的 `cue_hold`，不再否决当前直接观测到的人物。现有置信度、几何、友军、尸体形态证据、身份关联及手动转火规则继续执行。

没有增加等待时间、延长首发窗口、调低识别阈值，或添加新的场景开关。两个旧尸体测试把“标记消失、人体仍直立”直接当成死亡，现改为提供实际的扁宽身体形态；新增回归专门保护持续直立人物。仅靠黄色标记缺失，无法可靠区分活人与仍直立的死亡动画；这个信息不足不能通过永久否决活人解决。

运行：`cod_native_base_tests.exe --suite BaseVisionSelection --case marker_loss_live_person_incident --artifacts <output-directory>`。完整测试省略 suite/case。

## 尚待实机确认

压缩视频回放中，约 10.15–10.60 s 仍有真实的模型漏检；本次选择器修复不会凭空生成检测框。更早接入是否足以改善这次首发，需要重新编译后的实机验证，不能用固定录像的离线回放宣称命中率已经改善。其他片段的零输出和意外转火仍是独立问题。

全片回放的身份切换序列也有变化（修改前 6 个 generation，修改后 8 个），不以这个总数判定改进；关键 37 帧保持同一身份。其他区间的身份质量未做实机验收。
