# 桌面工作空间

2026-10-08 起，`启动助手.vbs` 的默认界面使用 Python + Edge WebView2 承载 React 页面。视觉采用已确认的早期 OriginOS 方向：不透明表面、柔和阴影、轻微实体感，以及有主次的模块大小。参数、曲线和范围预览可以直接操作；菜单与弹窗采用 Radix 组件处理焦点、键盘和关闭行为。

## 打开与构建

当前工作区已经安装桌面依赖并构建页面资源，关闭旧界面后重新打开根目录的 `启动助手.vbs` 即可。关闭界面不会停止原生控制程序。

在新环境或修改前端后，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup_desktop.ps1
```

脚本使用现有 `D:\env\python\python.exe`，没有该路径时使用 PATH 中的 Python；安装固定版本 pywebview，通过 `npm ci` 按锁文件安装组件，再构建本地页面。环境需要 Node.js 22 和 Windows Edge WebView2 Runtime。生产启动不依赖 Vite 开发服务器，也不连接在线页面。构建资源位于 `python/desktop_app/web_ui/dist/`，不纳入源码版本管理；缺少资源时启动器会明确显示构建方法。

`python -m desktop_app.gui --action ...` 的现有命令行入口保留。无 `--action` 时进入新桌面宿主，并沿用项目级单实例锁。

## 日常操作

新建配置只填写名称，不选择预置游戏。新配置从原生默认值建立独立快照，顶部“选择模型”读取实际 TensorRT 输入尺寸；规格需要调整时显示变更清单，确认后载入草稿。启动前再次检查模型、校验参数，然后保存和启动。

每份配置保留独立草稿，切换页面或配置不丢弃修改。顶部“保存并应用”和 Ctrl+S 使用同一流程。当前配置正在运行时尝试热加载；需要重启的变更会明确提示，并把主按钮改为“保存并重启”。保存成功但启动或加载失败时，界面保留成功保存后的版本，同时显示失败原因。

调参按“首次瞄准 / 持续跟随 / 输入与手动 / 目标与识别 / 开火与压枪”切换，阶段参数与范围预览同步。设备页分为“模型与采集”和“手柄与诊断”。工作空间标题与顶部操作固定，只有任务内容区允许滚动，并预留滚动条宽度，避免展开高级项时横向挤压。此前浏览器窗口尺寸未扣除桌面标题栏；实际 1360×940 宿主的内容区为 1344×901（本机 100% 缩放）。七个分类在 1344×901、1008×729、824×601 内容区中检查默认占高，并等待范围数据加载完成，21 个场景均无需滚动。高级项展开、长配置列表或错误提示占用额外空间时，内容区可以正常滚动。范围图按检测范围取景，拖动目标时不改变缩放比例。

字段问号点击后打开持久说明浮层，支持关闭按钮、外部点击和 Esc；关闭后焦点返回入口。没有说明的字段不显示问号。高级项使用浅绿色入口、参数数量和方向箭头；不放置改变文字缩进的左侧图标。主卡片标题、展开入口与展开后的字段文字左对齐。参数行统一保留底部分隔线，两列布局不再单独省略右下角边线。展开后显示边框与分隔，收起恢复高度。配置列表使用分离的圆角行代替贯穿行底的直线。

曲线支持拖点、精确数值、插入与删除点、撤销重做、预设以及 JSON 导入导出。精确点位输入需要点击“应用点位”；未应用时保存会提示，切页保留输入。端点固定，输入与响应严格递增。普通数值通过共享参数目录显示单位和范围，越界值不会写入配置。

范围预览读取原生几何策略，支持首次瞄准 / 持续跟随切换、目标姿态与高度、拖动目标和近中远位置。图下输出是静止目标、线性响应假设下的示例，不是实际游戏中的控制输出。

完整配置编辑先经过原生校验，再载入草稿。没有表单控件的合法原生参数也随草稿保留。导入依据文件中实际存在的分支选择；导出不覆盖受管理配置库。删除配置前需确认，运行中的配置不能删除，已保存文件移入 `runs/desktop/deleted-profiles/` 留作恢复。

## 代码职责

| 文件 | 职责 |
| --- | --- |
| `python/desktop_app/web_host.py` | WebView2 窗口、原生文件选择器、关闭事件与 JS 桥 |
| `python/desktop_app/web_service.py` | 草稿校验、乐观版本检查、配置 CRUD、模型检查、运行管理接口 |
| `python/desktop_app/web_ui/src/main.jsx` | 当前配置、草稿、异步操作、主导航与对话框流程 |
| `fields.jsx` / `controls.jsx` | 参数控件和共享菜单 |
| `curve-editor.jsx` / `preview.jsx` / `feedback.jsx` | 曲线编辑、原生规则预览、运行反馈 |
| `surfaces.css` / `app.css` | 已定稿的视觉体系与功能组件布局 |

配置读写复用 `workspace.py`，原生进程管理复用 `runtime.py`。Python 没有新增控制或 Vision 执行路径。异步操作通过桥接线程执行，界面线程负责交互。Windows 的关闭回调必须先返回，再异步调用页面确认，否则等待 Edge 执行 JavaScript 会造成界面线程互锁。

## 验证及边界

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'python'
python -m desktop_app.test_desktop
python -m desktop_app.test_desktop python/tools/benchmarks/desktop_web_host_smoke.py
python -m desktop_app.test_desktop python/tools/benchmarks/desktop_launcher_smoke.py
```

144 项桌面测试通过，其中 13 项桥接测试覆盖独立配置、数据类型与范围、冲突保护、新配置的模型选择、模型规格、保存后失败状态、完整配置往返及原生几何。实际 WebView2 宿主在隔离 Windows 桌面中验证启动、加载、五页默认内容高度、未保存草稿与关闭取消。

浏览器操作检查覆盖五个页面和三种窗口尺寸、折叠空间恢复、菜单与弹窗键盘焦点、草稿切换、百分比保存、拖点撤销、点位未应用时阻止保存、曲线与配置文件往返、复制重命名删除，以及模拟运行的启动 / 热加载 / 重启。脚本与截图在 `output/desktop-web-20261008/`。测试服务器仅绑定 localhost，使用临时配置库和不输出控制命令的运行替身；不纳入生产宿主。

现有真实模型的只读检查返回 480×384。自动化验证没有启动实际手柄控制或游戏，因此模拟运行检查不能代替用户的实际游戏验收。

2026-10-08 补充：复现 1500×820、1500×801、1344×801 内容区的预览溢出，原因为图示依据窗口高度断点估算，而非实际剩余高度。现在由 ResizeObserver 测量任务区、分类栏与预览说明的实际高度，分配图示尺寸；保留最小可读尺寸，极小空间或展开示例设置时仍允许内容滚动。上述尺寸回归、三尺寸标题/字段对齐与四个采集字段边线检查通过。


启动响应优化：模型规格检查以模型文件和原生可执行文件的路径、文件标识、大小及纳秒时间戳为依据复用同一次检查结果，仅保留最近一项。文件变化后重新检查，检查失败或读取期间文件变化不保存结果；真实启动仍加载模型。当前机器一次读取约 288 ms，随后两次约 0.37 / 0.27 ms，此数据不是端到端启动耗时。

启动按钮在检查期间原位显示进度并禁止重复提交。启动 RPC 返回创建的进程记录，界面立即进入“正在启动”，不等待一秒轮询；该阶段不宣称已经运行。后续状态读取判断运行、等待手柄或失败。早于启动响应发出的状态请求不能覆盖更新后的状态。浏览器延迟响应测试验证一次提交、立即进度、启动响应和旧轮询回包的顺序；使用运行替身，未启动真实控制输出。

独立设计需求见 `GUI_DESIGN_REQUIREMENTS.md`。它面向没有历史信息的设计 agent，不包含现有界面配色、布局或截图，适合独立生成后比较。

### GUI 分批提交的原生依赖

本次 GUI 提交同时包含启动所需的只读 `--inspect-engine` 接口。范围示例使用 `range-response-v4`；对应原生控制算法与几何策略输出仍属于工作区里的另一组改动，没有随 GUI 提交。上面的 144 项测试是在包含这些原生改动及已构建程序的完整工作区中运行的，不代表单独检出此 GUI 提交后，从旧原生源码构建也能通过。分发或独立重建前需合入匹配的原生改动。`dist` 和 `node_modules` 不入库，使用 `scripts/setup_desktop.ps1` 安装并构建界面。

压枪输出范围（2026-10-08）：开镜压枪输出统一为 1%–50%（配置值 0.01–0.5），默认 20%。关闭使用“固定力度压枪”开关；腰射按保留比例乘算，不抬回最低值。GUI、保存校验和原生加载使用同一参数目录；越界旧值明确报错，不自动钳制或覆盖用户配置。


### 双击入口首次不显示窗口（2026-10-08）

根因是 `启动助手.vbs` 使用 `WScript.Shell.Run command, 0, False`：隐藏启动标志会影响 pythonw 创建的首个 GUI 窗口。实际入口在私有桌面复现为约 841 ms 创建窗口，但 30 秒后仍不可见；此前只调用 `web_host.launch` 的测试绕过 VBS，因此没有发现。重复启动时，已有实例唤起逻辑可能通过 ShowWindow 恢复窗口，表现为需要多次双击。

入口改为正常显示（窗口模式 1）。pythonw 自身不创建控制台，无需使用隐藏模式来避免黑框。同时明确传入脚本所在项目的 `--root`，使入口和实例锁使用同一项目路径。实际入口复测约 964 ms 显示；新的隔离入口回归在含中文和空格的临时项目路径上，两次分别约 1090 / 1113 ms 显示并正常关闭。直接宿主的首屏可操作测量约 1.2–1.3 秒。这些是本机测量，不是所有机器的时间保证。

`desktop_launcher_smoke.py` 复制真实入口到临时项目，使用私有 Windows 桌面验证首次启动可见，不读取用户配置或启动控制输出。`desktop_web_host_smoke.py` 继续覆盖桥接加载、五页布局与未保存草稿关闭保护。没有采用试验中无明显收益的浏览器目录复用方案，也没有添加常驻后台或启动延时。
