## 优先研究：姿态边界造成的瞄点跳变

生产 `body_aim_geometry` 在高宽比 0.65 两侧分别使用 `wide_low_ratio` 与 `ordinary_ratio`。本次仅修复了准入范围，瞄点公式仍保留既有的分段切换。

探针固定左上角 `(270,220)`、宽度 100 px、置信度 0.92；高度每 100 ms 在 64.8 与 65.2 px 间切换。普通/宽扁瞄点比例固定为 0.20/0.65，不表示每个用户 Profile 都使用这两个值。

| 高度 | 原始瞄点 Y | 控制器源瞄点 Y | 探针输出 Y 示例 |
| ---: | ---: | ---: | ---: |
| 64.8 px | 262.12 | 262.12 | 第 90 ms：−0.20 |
| 65.2 px | 233.04 | 233.04 | 第 110 ms：+0.340148 |

框高度仅变 0.4 px，源瞄点跳变 **29.08 px**，同一 target_id 下输出方向随之翻转。证据为 `runs/dev-clean-sync-20261018/probes/geometry-sweep.csv`。这是通过真实生产链验证的几何不连续；探针固定画面、不把输出反馈到画面，所以不能把输出幅度当作实机振荡幅度，也未证明它是原视频的剩余根因。

建议下一次实验在**源几何估计层**研究连续的胸部参考，让框比例的微小变化不制造大的瞄点位移。应同时覆盖遮挡、宽扁/直立、多种瞄点比例、目标切换，以及控制器的源点不被手动改写。不能仅移动阈值、添加等待开关或让手动输入编辑瞄点；框形状也不足以证明头/胸可见性。本轮未实施该候选。

## 第二方向：降低观测年龄与长尾

保持相同种子和输入节奏，只增加合成视觉结果延迟。固定 tracking 窗口为每周期第 100–1500 ms，包含没有目标时的误差，避免只在有效辅助帧统计。结果如下：

| 额外延迟 | 窗口平均误差 | 辅助有效 tick | 相对基础误差增大的案例 |
| ---: | ---: | ---: | ---: |
| 0 ms | 130.379 px | 890,956 | — |
| 6 ms | 133.055 px | 861,217 | 90/128 |
| 12 ms | 134.394 px | 839,961 | 93/128 |

增加 12 ms 后辅助有效 tick 减少约 5.72%；同时有 35 个案例误差下降，不能声称每例单调恶化。这个实验说明当前合成闭环对时效敏感，**不证明已找到能节省 12 ms 的实现**。详情见 `latency-sensitivity.json` 与 `dev-delay-*/seed-*.csv`。

下一步应区分捕获/呈现年龄、GPU 工作与等待、发布到消费的各段长尾，优先缩短新鲜证据到达时间，保持 32/40 ms 限制。旧视频末段 capture-to-output p99 为 21.32 ms，ready-to-consume p99 为 1.039 ms；这些是旧会话描述，不是新运行的性能。没有依据先放宽来源时限或重写 mailbox 锁。

## 已有实验排除的方向

DEV 的 `output/vision-optimizations-20261013/RESULTS.txt` 已比较 CUDA 等待与直接纹理预处理：合成图形竞争下，忙等没有降低平均延迟，CPU 成本约 3.7 倍；直接读取的平均时间增加约 10.2%、p99 增加约 16.5%。这些结果不覆盖全部真实游戏，但足以否定“减少一次复制就必然更快”的理由。本轮没有重新启用这些候选。

当前证据支持先研究几何连续性，再定位观测长尾。实机跟踪效果、模型完全漏检与实际设备输出仍待新日志/视频验证。
