# 第一个案例：瞄具遮挡、cue连续性与手动输出

用户纠正重点：23:30剪辑的第一个案例，而非翻窗。关注小幅横移被瞄具遮挡后辅助减弱/消失，以及约30%协作手动输入突然完整透传造成拉过头。本轮仅诊断，未修复生产逻辑，未改配置或clean。

## 方法与边界

使用现有`vision_cue_video_review`，重新链接当前生产Vision库，读取原模型`models/best_480x384.engine`。对合并视频前3.28秒逐帧解码、中央640×512裁剪，以生产GPU预处理、TensorRT模型、裁剪颜色ROI和VisionTargetSelector回放197帧。参数190/.2/.65/friendly=1与启动profile一致。

产物`runs/live-escape-20261018-2330/first-replay.jsonl`、`first-frame-times.json`、`first-replay.log`、`first-cue-evidence.png`。视频约60fps，诊断工具按60fps赋capture时间；与实机200Hz截图、latest-only消费及视频压缩存在保真差异。没有23:30逐帧控制日志（启动telemetry=off），也没有实际LT/右杆输入，不能据此断言本次阶段、输出或每个丢目标事件。

## 已确认缺陷：未选中检测会阻断有效cue观测的传递

生产路径：

1. `runtime_app/vision_controller_adapter.cpp:130–180`保留非友军、class0且几何有效的检测用于候选/诊断。选择器拒绝它并不从原detections列表删除它。
2. `native_gamepad_controller.cpp:495`仅在`batch.count==0 && selector_cue_continuation`时构造正式cue观测。只要带了一个上述未选中框，cue几何就没有被构造。
3. `target_coordinator.cpp:111–132`要求cue为同代际、唯一候选、source_id=0且有cue几何。残余人体候选有非零id，因此拒绝；两个以上残框也会因count不为1拒绝。
4. 于是原本新鲜有效的cue结果，被当成缺帧。缺帧链继续按原32/40ms和空间/手动条件工作，而不是消费新鲜标记。

最早被违反的不变量是：**诊断用的未选中人体框，不应取代或阻断选择器已经明确授权的同代际cue延续。** 责任在视觉结果到控制观测的转换，不是cue匹配阈值、最终手动透传或32/40ms本身。

2.017秒回放恰好出现了这类输入组合。但这一帧不是该片段最早出现偏差的时刻，也不能仅由单帧推定必然达到身份超时；不能把此缺陷说成整个第一案例的唯一实机根因。

## 生产反例与邻接路径

独立诊断夹具`runs/live-escape-20261018-2330/probe/`链接当前controller_native_core，使用生产NativeGamepadController和原始手动输出仲裁，不连接设备。

输入：1000Hz控制、5ms新鲜观测；先正常人体，再同代际cue；固定位置偏差20px、手动X=.30、LT保持，原40ms期限及32ms缺帧预测。不是视频实际输入或闭环相机重建。

- 无残框：cue每5ms被接收，源年龄持续刷新，ADS和目标保持有效。
- cue持续附带一个未选中的.34残框：生产进入observation_gap，源年龄不再被新鲜cue刷新；原源年龄约32ms边界停止辅助，40ms后释放身份，输出恢复原手动.30。
- 只有一次残框，下个5ms cue干净：同一目标恢复cue，没有必然完整丢失身份。说明不能把视频单帧残框直接夸大成整段40ms失踪。

结果`probe-result.txt`，chain列为variant,tick,mode,cue_continuation,observation_gap,aim_authority,target_id,output_x,source_age_ms。模式1为ADS、0为Manual。浮点32ms打印值不可用来推断精确比较符变化。

## 另一条已复现机制：目标没丢，也会发生协作力度变化

BodyLock的原始人体可靠度同时参与最终预算，以及手动/AI仲裁的证据系数。`assist_control_state_machine.cpp:211`把视觉权限.65～1映射为0～1的协作证据；`257`附近的当前位置主导要求直接人体观测，cue延续不走同一路径。弱人体关联可以保留身份，但低置信度使上述约束显著减弱；cue切换又改变直接位置主导资格。

锁定同一输入的生产仲裁探针：手动X=+.30、AI请求X=-.10、目标偏差X=-20、手动活动权重1、无明确退出/修正、其余量固定：

| 情况 | 最终X |
|---|---:|
| BodyLock直接人体，视觉权限.84 | +.0568 |
| 直接人体，权限降至.35，目标身份仍有效 | +.3000 |
| cue延续，权限仍固定.84，仅改变观测类型 | +.2430 |
| 目标失去权限 | +.3000 |

另一个ADS名义阶段探针：相同手动+.30、AI+.08，目标有效时+.08；失去权限后+.30。

这些证明用户描述的“同样的手劲，在辅助变化时输出突然变大”是当前生产机制能产生的，不需要假设用户突然加力。它们不是本次实际杆量、也不是完整仿真，尤其不能认定1.68秒当时必为BodyLock。人体置信度降至.35并不会按同样方式缩小已获准ADS；两种阶段必须区分。

证据不足时减少辅助、失去权限后恢复手动本身有合理职责，不能直接把所有此类变化判成缺陷或擅自保持旧抑制。需要审查可靠度、运动需求、手动意图与观测类型的职责是否造成不必要的行为突变。绝不能通过丢目标后继续压住手动、提高cue预算、延长旧坐标时效来掩盖。

## 当前结论

第一案例更准确的描述是：镜框附近人体检测变弱/消失，视觉来源频繁切换；cue有时已经成功，但可能在控制观测转换中被残框阻断；即使身份还在，BodyLock证据变化也能明显放出原来受约束的手动输入。已确认一个接口缺陷和一种可复现输出变化机制，尚缺本次实机阶段/输入日志以判定各自贡献。

后续优先在原权限及32/40ms内修正cue观测与诊断候选混用，再分别验证observed/associated_weak/cue/gap转换时、固定30%手动下的输出连续性与原手动权。修复范围须保持源胸部、身份代际、新鲜性和无cue开火权限。本轮只定位，不实施修复，不合clean。
