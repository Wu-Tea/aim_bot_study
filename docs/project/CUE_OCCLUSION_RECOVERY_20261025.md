# 跳跃、滑铲与机瞄遮挡：cue 恢复修复

用户提供 QQNT 12.19.03.04 / 12.20.24.05 两段录像，并指出人体被矮墙和机瞄临时遮挡后跟丢。用户确认它们是直接录制，发灰来自 HDR，授权自行处理录制色彩。修改落在 dev，未提交、push 或同步 clean。

## 输入与复现

两片分别 7,316 / 2,756 帧，总计 10,072 帧，1920×1080、120 fps。编码元数据为 HEVC Main10、BT.2020、PQ（smpte2084）、full range。直接把 PQ 数值当普通 BGRA，会把洋红标识压灰；原始错误解码回放中 cue 检出为零，不能据此改生产颜色阈值。

离线回放先按视频元数据解码到线性光，再转换 BT.709、Mobius 色调映射、BT.709 输出；保持 640×512 中心裁剪、真实 PTS 和逐帧检测。具体滤镜保存在每段 complete.json 和测试脚本中。色调映射只用于录像验证，不修改生产 capture、颜色阈值、用户 Profile 或原视频。该 SDR 映射不是游戏实时截屏逐像素真值。

第一段约 6.35 秒，cue 本身确实短暂消失，人体检测随后也受遮挡影响。约 6.63–7.14 秒 cue 已回来，但原逻辑已把身体标定一起清掉，遮挡期间没有新完整 person，因此连续 62 帧没有目标。不能把前面 cue 真正消失的帧描述成检测器漏检。

第二段约 13.11 秒，模型把背景假人与被机瞄遮挡的敌人合成较高的框，框顶长到 cue 上方。“完整身体恢复”分支把它当成反证，清掉了仍连续可靠的 cue；随后约 13.30–13.66 秒连续 44 帧有 cue 却没有目标。

## 最终实现

1. **标定寿命和输出权限分开。** 当前 cue 丢失仍沿原来的 50 ms 规则失去新鲜身份；person 的原有身份释放和弱框准入规则保持。最近真实 person 关联过的身体标定，可在原有 180 ms 几何证据期限内保留。期限从真实 person 观测计时，空帧和 cue-only 输出不续期。保留标定本身不输出瞄准或开火。
2. **当前 cue 唯一匹配后恢复。** 使用原 cue 匹配的距离、大小比和歧义要求；只在最近标定附近搜索，结合最后人体位置平移参考。原控制身份已释放时建立新身份，避免继承旧速度状态。cue 恢复只给 aim 权限，不给 fire。过期、多个 cue 无法区分、显式 reset/退出或换目标均不能沿用旧标定。
3. **恢复身体必须有合理的 cue 几何。** 单帧框变高不再能推翻可靠 cue。真正补回先前缺失的上半身，应从 cue 下方接近头部，保持身体范围的支撑；框吞进 cue 上方背景、或放大后离 cue 更远，都不能重建标定。正常身体缩放仍走原一致性验证，完整身体返回可以立即接纳。独立 person 确实移出旧 cue 时，用上一帧实际人体框判断连续运动，保持 person OR cue 的权威边界。

没有加入 Off 减速，没有更改 controller 力度、ADS 参数、手动权限、检测频率或模型。没有采用把横向偏移长期固定的实验；旧素材表明它会锁住初始偏差，最终代码已撤下该约束。

## 限制

cue 能提供稳定的标识位置，不能单独证明人体完整轮廓、姿态或真实胸部深度。跳跃/滑铲改变人体形状，或身体与 cue 都长期不可见时，不保证恢复真实胸部位置；本次不宣称所有姿态误差已消除。初次就标定到残框，以及模型高置信度把枪身/背景当人，仍有局限。

没有对应真实手柄轨迹；控制拟真使用合成输入，视频已有镜头运动，近似闭环不会重渲染。测试和阶段耗时不等于游戏实机验收或实机 FPS。
