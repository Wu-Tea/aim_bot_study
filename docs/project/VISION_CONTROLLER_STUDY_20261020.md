## 1. 确认：person → cue 会收缩 BodyLock 范围，造成辅助中断

实际回放例子：补充录像 v1 的 **10.763–10.796 秒**。同一 Controller 目标 ID 14，person 转 cue 时胸部点只移动约 **2.06 px**，身体框/瞄准区域几乎不变，但辅助权限由 **0.845215 → 0 → 0.893066**；中间 16 ms 的 cue 段输出为零。dev 主录像 **88.331 秒**也有同类事件，切换时胸部点约移动 3.03 px，权限由 0.794922 归零。

全片中性输入重放发现 **58 次**同一目标 BodyLock 从 person 转 cue、权限从正数降到零的事件，其中 **37 次**来源点移动不足 5 px。这是此重放设置下的事件数量，不是实机发生率，也不是 58 个独立根因。

根因在 `native/controller_native/target_coordinator.cpp:893` 附近：

```cpp
const float observed_body_size =
    lifecycle == TargetLifecycle::Observed ? normalized_size : 0.0f;
```

此值用于 `target_scaled_radius`。person 使用身体大小扩大后的范围；同一身体参考进入 `CueContinuation` 后，大小被置零，范围退回 Profile 的 120 px。后续 `bodylock_outside_activation_range` 立即清零 `aim_authority`。不是胸部点漂移、目标换代、时间过期或手动退出引起。

固定几何探针先让 ADS 在中心完成，再固定身体框和胸部点，只切换 person / cue / person。12 个高度/距离组合中有 **6 个**复现来源单独造成的中断；身份、胸部坐标、cue 无开火权限等检查均通过。代表例：

| 身体高 / 胸部距离 | 来源 | 跟随范围 | 辅助权限 | X 输出 |
|---|---|---:|---:|---:|
| 220 / 145 px | person | 158.672 px | 0.9 | 0.9 |
| 220 / 145 px | cue | 120 px | 0 | 0 |
| 220 / 145 px | person 返回首 tick | 158.672 px | 0.9 | 0.064 |
| 220 / 145 px | person 返回后 | 158.672 px | 0.9 | 0.9 |

建议优先修正同一目标身体几何在这两种来源下的范围计算职责。使用经过确认、仍由新鲜 cue 续跟的身体参考时，不应仅因来源枚举变化而丢掉已有尺度；保持 Profile、输出上限、手动权限、32/40 ms 时效和 cue 无开火边界。这里是已确认的有限场景缺陷（P2），本轮未实施修复。

证据：`runs/vision-controller-study-20261020/radius-probe.csv`、`radius-events.json`、`radius-transition.svg`，固定几何探针源码 `tests/vision_controller_study_20261020/radius_probe.cpp`。

## 2. 确认：黄色命中提示的四个端点进入 cue，错误延续旧身体参考

dev 主录像 **190.075 → 190.083 秒**：

| 字段 | 前一帧 | 后一帧 |
|---|---:|---:|
| 视频帧（1 起算） | 22810 | 22811 |
| selector generation | 100 | 100 |
| 来源 | person | cue |
| 胸部 X / Y | 13.916667 / 258.066681 | 292.25 / 234.600006 |

一帧移动 **279.32 px**，身份没有换代。对应图像中人体已在截取框左边缘，中央是黄色命中提示。对原始像素重新调用生产 `CueDetector`，四个端点全部被接受：

| X | Y | size | score |
|---:|---:|---:|---:|
| 309.5 | 244.5 | 14 | 0.890071 |
| 332.5 | 243.5 | 12 | 0.815211 |
| 307.5 | 267.5 | 12 | 0.753382 |
| 332.5 | 267 | 11 | 0.719357 |

最后一次保存身体参考在帧 22792（189.925 秒）：胸部 `(266.25, 257.600006)`，cue `(306.5, 266.5)`。将误认的 `(332.5, 243.5)` 代入参考平移，恰好得到 `(292.25, 234.600006)`，与输出一致。之后 person 继续向左运动，但没有新的可靠 person/cue 配对替换这份参考；人体消失时旧参考被命中提示继续驱动。

最早失效边界属于 Vision：`cue_identity.cpp` 的颜色连通分量被当作目标标记；`target_selector_fusion.cpp` 的配对/续跟未排除这个 HUD 关联。不能通过增加 Controller 力量、平滑或等待掩盖。Controller 另外有 cue 关联半径保护，因此这次 279 px 跳变**不等于 Controller 实际输出了同等幅度的甩枪**；已确认的是错误目标几何进入了边界。

建议为命中提示的整体结构和相对运动增加可辨别证据，并在人体与所跟 cue 明显分离时撤销这份关联。需要覆盖真实头顶圆点和死敌骷髅，保留正常标记靠近准星的场景。这是有限场景的 Vision 误关联（P2），本轮未实施修复。

图像证据：`runs/vision-controller-study-20261020/dev-190-pair.png`。像素检查工具：`inspect_cue.cpp`。全素材还筛出 359 个同代相邻有目标帧超过 40 px 的来源点变化，其中 156 个涉及 cue；这些只是待核对事件，不能全部当作误识别。

## 3. 本轮实验覆盖

### 像素重放

两段用户录像完整重放，并加入项目已有 9 段 COD 录像。解码得到 **44,205 帧**。两段主录像各比容器声明帧数少 1 帧；FFmpeg 与原生导出进程正常结束，报告按实际解码计数。中间检测空帧也完整保留。

| 素材 | 实际帧数 | 新 Vision 有目标帧 | cue 延续帧 |
|---|---:|---:|---:|
| clean，00-29-16 | 15,572 | 7,261 | 1,450 |
| dev，00-25-46 | 23,198 | 10,817 | 2,253 |
| 补充 v1–v9 | 5,435 | 1,951 | 271 |
| 合计 | 44,205 | 20,029 | 3,974 |

这些是输出覆盖计数，没有人工真值，不代表准确率。原始图像按中心 640×512 截取，使用现有 `best_480x384.engine`，保留真实身体框、胸部点、瞄准区域、cue/像素运动锚点、置信度及 selector generation。

### 全片 Controller 重放

33 组，**1,241,550 个 1 ms tick**：每段中性输入/6 ms、输入变化/6 ms、中性输入/28 ms 三种设置。clean 的输入变化组使用遥测右摇杆和 LT，视频时间按既有 `.89 s` 偏移近似对齐；其余片段使用显式固定输入。RB 只采纳遥测明确的 `manual_fire` 原因，不把最终开火按钮当作原始输入。

中性组从开始持续 ADS，主要用于检查连续 BodyLock 的来源与权限边界；不模拟整段录像中玩家的全部 ADS 操作。虚拟输出不改变视频，所以不以这组输出计算跟踪改善或超调。未建立反事实闭环时，运动估计/学习量也不能当作实际游戏估计值。

### 录像几何驱动的闭环压力仿真

25 个窗口，6 种输入，2/20 秒，4 个种子：**1,200 组、13,200,000 tick**。探索种子 `71020261/71020279`，另用 `71020303/71020321` 验证。最终比较中，同一窗口的输入组及长短组共享物理参数；早期探索产物不作为最终矩阵结论。

- 保持 1575 ms 目标槽 + 50 ms 间隔，Controller 1000 Hz，实际录像的 120 Hz / 约 60 Hz 观测节奏。
- 相机响应 900–2500 px/s/归一化响应，输出延迟 6–30 ms，视觉交付延迟 4–20 ms；使用 Profile 的响应曲线映射。参数是压力假设，未声称由录像标定。
- 输入分别为中性、固定 `(0.20,0.12)`、X 反转并保持 Y、95% 强退出、RB 开火及匹配 0.2 压枪扰动、固定 `(0.30,-0.18)`。固定偏置不是理想玩家或协作策略。
- 保留实录来源/漏检/身份时序，将所有身体、胸部、cue 和像素锚点按模拟相机位移一起平移，再由真实 Controller 计算输出并反馈到模拟相机。
- 录像中的屏幕位移本已包含原玩家的相机运动。本模型把它当外部残余扰动，**没有还原世界坐标**；画面不随新输出重新渲染，检测器也不会因目标移出截取框而重新决策。保留的是实录证据形状和时序。
- Controller 的手动退出得到检查，但结果没有反馈给离线 selector 重新索敌。因此主动退出/大偏置下的巨大残余误差不能直接判成 Controller 缺陷。

所有最终组均未触发以下检查：输出有限且在物理范围内；身份不超过 40 ms；漏检超过 32 ms 不续权；胸部来源点不被手动输入改写；明确退出保持手动透传；未 ADS/开火时原始透传；cue 不获得开火权限；ADS 与 BodyLock 不同时拥有定位职责。

这些检查通过只表示所查边界成立，不证明跟踪品质最优。clean 121.5 秒含 person→长 cue 的窗口，中性组短/长残余误差均值 **6.35–13.67 px**、P95 **15.21–45.19 px**，没有一律在 180 ms 截断；不同相机假设仍有明显变化。这里的误差是相对录像选定几何的仿真量，不是实际胸部误差或命中率。

另外保留从 clean 122 秒纯 cue 段冷启动的负对照：8 个中性短/长组均没有凭 cue 建立新目标，这是既定的“先有身体参考才能续跟”边界，不记作失败。

## 4. 建议后续顺序

1. 修 Controller 的 BodyLock 几何范围在 person/cue 切换时不一致；用本轮固定几何探针和对应视频回归。
2. 修黄色命中提示被当作 cue 的关联问题；以原始像素、头顶圆点及骷髅素材验证，随后重放完整链。
3. 再用实机遥测评估残留振荡、ADS 完成和 BodyLock 持续跟随。当前压力仿真不足以把所有高误差案例归因到控制算法。
