# 原生 gamepad 输出切换为 DS4

日期：2026-09-19

用户要求把 DSE 经项目输出的虚拟 Xbox 360 直接改为虚拟 DS4。
当前 C++ `cod_native_runtime` 固定创建 ViGEm 有线 DualShock 4，沿用原
gamepad / Fusion 启动器，无新增配置开关。Python 旧入口不在本次范围内。

## 改动

- `virtual_gamepad.cpp` 使用 `vigem_target_ds4_alloc` 和
  `vigem_target_ds4_update_ex`。初次连接和恢复连接都提交完整中立报告。
- `ds4_output_report.h` 在唯一输出边界编码完整 63 字节报告。
  摇杆中心为 128，范围为 0..255；把内部正 Y 朝上的约定转换为 DS4
  正 Y 朝下。没有新增平滑、死区或响应曲线。
- 映射面键、L1/R1、L3/R3、Share/Options、PS、触摸板按压和八方向 D-pad；
  L2/R2 同时写模拟量与相应数字按键位。相反 D-pad 输入按轴抵消。
- 未提供的陀螺仪和触摸输入不继承驱动默认样本；触摸接触点标为抬起。
  触摸板坐标/滑动、陀螺仪和 DSE 独有按键不转发。
- 不更改 ADS、BodyLock、手动权限、AutoFire 或压枪的控制算法。
  现有内部浮点输出记录仍是编码前命令，DS4 的 8 位量化在传输边界发生；
  这些浮点记录不应当作游戏实际收到的精确轴值或端到端延迟证据。
- SDL 输入在虚拟输出创建之前打开；重连匹配原设备名称及控制形状。
  回归用例覆盖 DSE 断开后不能接入本项目的 `PS4 Controller`。
  同名同型号多设备和外部转换软件的选择歧义不由本次切换解决。

## 验证

本机 ViGEmBus 1.21.442.0；现有 DLL 导出所需 DS4 接口。

Release 构建：`cod_native_runtime`、`cod_native_base_tests`、
`cod_native_functional_tests`、`cod_native_ds4_smoke`。

```powershell
ctest --test-dir native/vision_native/build -C Release -R '^(Base|Feature)' --output-on-failure
& native/vision_native/build/Release/cod_native_ds4_smoke.exe
```

- 10/10 Base / Feature 套件通过。
- 新报告测试覆盖中立、回中、反向、端点、全部 256 个 Sony HID 轴值经 SDL
  归一化后的往返一致性、按键位、扳机、D-pad、无效值和未提供传感器状态。
- 本机驱动 smoke 创建并读回 `PS4 Controller`，一秒内 66 次中立读回通过，
  无输出重连，结束后释放设备。该计数受测试的普通 sleep 调度影响，
  不是生产报告率或延迟测量。
- Smoke 只输出中立状态，不运行 Vision、AI 或实体输入转发；它是手动执行
  的硬件检查，不加入自动 CTest。

## 使用及未验证边界

重新启动当前工作区的原生 gamepad / Fusion 启动器即可使用新输出。
游戏应选择虚拟 DS4；若游戏或启动平台再次把它转成 Xbox，需要先辨明实际
输入路径再评价手感。不要同时让游戏消费实体和虚拟两份输入。

用户提到早期 DS4 曾出现问题；当前文档、交接和相关 Git 历史未找到能够
确认原因的记录。本次没有把该旧问题归因为某一个映射或驱动缺陷。

游戏内识别、DSE 实体操作、8 位量化对微调/压枪的影响、回中与反向手感及
端到端延迟仍需实际使用确认。虚拟 DS4 不等于原生 DSE，也没有证据证明
本次切换必然更快或曲线更合适。

## 同日补充：逐键审计与触摸板按压修复

用户要求确认所有按键后，发现第一版只转发原 XInput 公共字段，缺少
触摸板按压：输入未读取、内部状态未保存、合成器未传递、DS4 特殊按键
bit 1 未设置。这是一个确定的转发遗漏，不是已确认的历史 DS4 故障原因。

新增 `PhysicalGamepadState.touchpad` 和 `GamepadOutputState.touchpad`，
通过 SDL 的 `SDL_GameControllerGetBindForButton(TOUCHPAD)` 在打开/重连时
解析真实 raw-button 绑定，逐 tick 读取并传到 DS4 报告。避免混淆语义
按钮编号 20 与 Sony HIDAPI 原始按钮编号 15；原始编号 16 是静音。

三个回归用例先观察到行为失败，再修复通过：
`ds4_touchpad_composition_release`、`sony_buttons_to_ds4_report`、
`touchpad_uses_sdl_device_binding`。后两个使用 SDL 进程内虚拟输入，运行
真实读取器、输出合成器和 DS4 编码器，不向系统/游戏发送按键。

逐键覆盖面键、Options、Create→Share、PS、L1/R1、L3/R3、D-pad、
触摸板按压和下一报告的释放；确认独立 mute/Fn/paddle 不误变成触摸板。
另有四根摇杆轴及两个扳机的各 256 个码值全链路检查。

| 实体输入 | DS4 输出／边界 |
| --- | --- |
| ×、○、□、△ | 对应面键 |
| 上下左右及斜向 | DS4 八方向 Hat；对向按轴抵消 |
| 左右摇杆、L3/R3 | 对应轴和按压 |
| L1/R1、L2/R2 | 对应肩键、模拟扳机及数字位 |
| Options、Create | Options、Share；截图行为由游戏/平台解释 |
| PS、触摸板按压 | 各自独立的 DS4 特殊按键位 |
| 触摸坐标/滑动、陀螺仪 | 未转发至虚拟 DS4；2026-09-23 起读取实体触摸坐标用于右上角连发，见末尾 |
| 静音、Fn、独立背键 | DS4 无同名按键，本项目不另作映射 |
| 背键在 DSE 配置中映射成普通按键 | 若 DSE 报告已反映为普通按键，则走对应普通按键链路；未实测当前配置 |
| 震动、灯光、音频、自适应扳机反馈 | 未实现游戏→实体 DSE 的反馈转发 |

当前未完成用户实体 DSE 的逐键实按验收；自动化结果不能替代这一边界。

## 同日补充：转写 0 死区，AI 裁决每轴 8%

以下记录最初的 8% 实现及验证过程；当前值已按用户后续要求调至 25%，
以本文末尾的补充为准。

用户澄清要求：AI 判断可以忽略约 8% 输入，但原始信号不要防抖。
原来的物理透传本身没有软件死区；2% 死区、噪声包络和中心偏置学习
位于意图解释层，不能据此认定原始信号被清零，也不能据此确认延迟原因。

现在实体 gamepad 的右摇杆意图解释与最终 AI 裁决共用固定每轴 ±8% 门槛：绝对值
不超过 0.08 不触发新的 AI 手势或目标点修正；超过门槛直接使用原值，
不减去 8%、不重映射行程、不学习/扣除中心偏置。X/Y 独立判断，因此
对角线 (0.07, 0.07) 也不触发修正。这是原生 gamepad 的默认策略，
不修改鼠标适配器的专用死区和空间噪声处理。

物理输入仍完整保存，纯手动/无目标时直接进入 DS4 编码，包含静止抖动、
小幅移动、回中和反向。AI 有控制权时仍遵循现有目标优先仲裁，不能把
“0 输入死区”理解成最终输出始终等于物理输入。已持有手势的回中交权
也消费同一个裁决门槛产生的活动度：门槛内为零，门槛外平滑过渡，
到门槛的 1.5 倍时为完整控制权；这是裁决权重，不是转写曲线或另一个
独立可设的死区。原先 2% 回中带和中心学习不再参与实体右摇杆裁决。
门槛外已被目标协调器接受的目标点修正直接参与原有裁决，不等待上述
持有手势权重升满，避免形成第二个修正准入门槛。
DS4 的 8 位量化、手柄固件和游戏自身的处理不在此软件死区保证之内。

回归新增 `gamepad_raw_passthrough_ai_deadzone_eight_percent`，先观察旧实现
在“AI 忽略每轴 8%”断言失败，再修改实现；覆盖持续小偏移、正负 8%
边界、8.1% 原幅值解释、中心附近 Sony 原始码经过控制器及 DS4 编码
逐码不丢失。另检查 gamepad 门槛不影响鼠标输入。

新增 `gamepad_shared_arbitration_deadzone`，先复现“上游已中立，但最终
裁决重新给予原始小输入控制权”的失败，再统一最终裁决消费的意图。
覆盖 ADS Snap / BodyLock 两种模式、正反向及两轴的 8% 边界和范围内
输入，并检查松开 LT 的同一 tick 恢复原始 1.2% 抖动。

旧 `small_filtered_input_has_no_second_deadzone` 和手动残余权限场景曾以
5% 作为有效修正。按此次明确要求，前者增加 5% 不修正、8.1% 当拍修正
断言；后者将触发输入改为 8.1%，边界对照改为 8%，报告 ID 标记此次
策略修订，保留原有权限和连续性数值断言。原始 5% 触发规则已经变更，
不能把这些结果表述为原历史夹具未经修改地通过。

最终 Release runtime / base / functional 构建成功，10/10 Base / Feature
套件通过；静止漂移、持有/释放交权、垂直修正释放等既有回归也通过。
这是软件契约验证，尚未测量实际游戏延迟或完成实体 DSE 手感验收。

## 后续调整：裁决死区每轴 25%

用户明确要求把裁决区域从 8% 扩到 25%。实体 gamepad 右摇杆现在每轴
绝对值 ≤0.25 时视为 AI 裁决中立，超过后使用原幅值解释手动意图。
ADS Snap 和 BodyLock 共用这一门槛，转写仍为 0 软件死区。
例如 (0.20, 0.20) 两轴都在裁决区内，但纯手动时两轴仍完整转写。

持有手势的控制权过渡仍沿用门槛外至 1.5 倍门槛的既有规则，因此
现在在 37.5% 达到完整持有权重；已接受的目标点修正不等待权重升满。
测试边界相应更新为 ±25% 和 ±25.1%，完整持有手势场景使用 40% 输入；
这些是授权门槛变更后的触发输入调整，不是原历史夹具不变的通过证明。
双轴新手势场景原先 Y=-20%，现在属于裁决中立，因此该场景改为
Y=-30% 以继续覆盖双轴有效手势；原有目标归属及修正断言保持不变。
25% 策略的 10/10 Base / Feature 套件通过。

## 2026-09-23：触摸板右上角按住连发

按用户要求，手指轻触并停留在触摸板右上角时，直接发送 fire 连发；移开或松开
即取消这路请求。不需要机械按压、实体 fire 键、LT 或目标，不是点击切换开关。
区域使用 SDL 归一化坐标 `x >= 0.75 && y <= 0.5`，即最右 25% 与最上 50%
的交集（按后续要求从上方 25% 扩大）。两个手指中任一个位于区域内即生效，
最后一个离开时停止。中线 `y=0.5` 属于上半区，不同时触发下半区。

读取器保持 SDL GameController 句柄，在原有输入采样中调用
[`SDL_GameControllerGetTouchpadFinger`](https://wiki.libsdl.org/SDL2/SDL_GameControllerGetTouchpadFinger)。
接触状态与触摸板按压分别保存；不用压力阈值。旧 SDL 缺少触摸接口、设备没有
触摸板、查询失败、坐标非法或手柄断开时，不产生触摸请求。

连发沿用 `[gamepad.auto_fire]` 的 `fire_output`、`pulse_width_ms` 和
`pulse_period_ms`。本地配置为 RB（DS4 R1）、按下 30 ms、周期 100 ms，约每秒
10 次。第一发立即开始；取消不等待当前 30 ms 脉冲结束。`auto_fire.enabled`
只控制原有基于目标的自动开火，不禁用这个显式手势。

TouchpadFire 只负责手势及脉冲时序，通过现有 FireCommand / OutputComposer
写入输出。触摸持有期间占用自动开火控制权，防止目标 AutoFire 填满脉冲间隙；
此期间不生成 RecoilContribution，包括松键间隙。触摸开火仍标记为开火干扰，
避免把射击造成的画面运动错误学成摇杆响应。它本身不激活 AI 瞄准。

原始摇杆、触摸板按压及其他实体按键继续透传。实体 fire 的按住状态仍保留，
所以同时按住实体 fire 时不会强行替用户释放它。离开触摸区域后，普通手动开火
的压枪与基于目标的 AutoFire 恢复各自原有规则；取消触摸连发不等于关闭 AutoFire。
鼠标适配器不使用触摸手势。

Release 主程序已重新编译。新增测试覆盖 SDL 读取成功/释放/失败、双指、区域
边界、机械按压隔离、断连、重置、RB/RT 到 DS4 报告、300 ms 内三个脉冲、
松手取消、无目标开火、无压枪、鼠标隔离和目标 AutoFire 的交互；10/10 Base / Feature
套件通过。当前本机未枚举到已连接手柄，实体 DSE 坐标与游戏实测仍待正常使用确认。

## 同日补充：右下角三角双击

最右侧 25% 的下半区（`x >= 0.75 && y > 0.5`）新增三角双击。进入该区域时
触发一次，按下 20 ms → 松开 20 ms → 再按下 20 ms → 松开。这里将用户所说的
“间隔 20 ms”解释为两次按压之间的释放间隔；两次按下的起点相隔约 40 ms。
轻触后松手仍会完成本次双击，持续停留不重复；离开后再进入才重新触发。
进行中的双击不排队叠加新请求，断连或 controller reset 会立即取消。

三角动作走独立的 AuxiliaryButtonCommand，在 OutputComposer 的辅助动作阶段
与 D-pad 合并，输出对应 DS4 三角位；不会伪造物理输入、激活瞄准或触发压枪。
不使用 sleep 阻塞控制线程。若 tick 延迟，仍先发送释放，并保留至少 20 ms 的
两次按压间隔。实体三角继续透传，按住实体三角时不会强制替用户松开。

新增原生控制器测试逐毫秒检查 DS4 三角位、两次点击及释放、短触/长按、重新触发、
断连/重置、双指、上下区中线、延迟 tick、鼠标隔离，以及辅助命令合法性与 D-pad
共存。触摸范围和触摸板按压是两个独立概念，机械按压本身不会触发区域动作。
