# 手柄助手：配置工作室

手柄助手现在以独立配置为编辑对象。一份配置保存自己的模型、辅助参数和响应曲线，游戏在创建时确定。切换配置只改变正在编辑的对象；右上角的运行状态始终指向实际运行的实例，点击“切换并启动”才会切换运行配置。

双击项目根目录的 **`启动助手.vbs`** 打开桌面 GUI。界面仍使用 Python 自带 Tk，滑杆、开关和选择菜单由轻量控件绘制，不需要安装新的 GUI 框架。

## 第一次使用

新配置库不会自动展示历史场景，也不会改写 `config.toml`。

1. 点击“＋ 新建”，填写名称并选择游戏。Apex、BO3 默认使用线性曲线，通用 / COD 使用原生 COD 动态曲线。
2. 在“设备与运行”选择 TensorRT `.engine` 模型。新配置的模型路径留空，避免误用此前训练产生的模型。
3. 在“参数调校”调整力度，或在“响应曲线”拖动控制点。点击“保存修改”写入配置；点击“启动配置”保存并启动。

需要使用已有参数时，从“配置管理 → 导入配置”选择原来的 TOML。导入时指定游戏，工具将基础值与该游戏的覆盖值解析成独立快照，原文件保留。旧版 `profiles/*.json` 元数据也可显式导入其同名 TOML。新版完整配置 JSON 自带游戏身份，导入时保留它并创建新 ID。

“配置管理”还提供复制、重命名、导出、重新载入和恢复创建时的参数。复制包含当前有效草稿，形成独立配置；重命名保留 ID；恢复创建时的参数先进入草稿，保存后才写入文件。重新载入会询问是否丢弃尚未保存的草稿。

## 四个工作区

| 工作区 | 常用操作 |
| --- | --- |
| 参数调校 | 两列显示开镜与跟随、识别目标、开火与压枪，共 12 项；按需展开四个响应初值 |
| 响应曲线 | 切换内置曲线、拖点、逐点精调、撤销重做、预设与 JSON 导入导出 |
| 设备与运行 | 模型、捕获与模型输入尺寸、手柄、检测帧率设置、日志开关、完整配置编辑和重启 |
| 运行反馈 | 原生运行与连接状态、四个响应学习区域、Fusion 开关、运行日志与学习数据导出 |

参数页支持按名称或字段路径查找，匹配响应初值时会展开高级项。右键参数或按 Shift+F10 可查看范围与恢复该项创建时的值。直接输入保留小数精度；非法输入留在原处、显示错误并阻止保存。切页和切换配置保留各自的草稿，互不覆盖。

滚轮在输入框、滑杆和关闭的选择菜单上用于滚动页面，不修改参数。鼠标经过控件不会取得焦点。选择菜单的上下键只移动候选，点击或 Enter 提交；Escape、Tab 或点击外侧取消，关闭后归还焦点。

## 手动曲线编辑

画布负责选点和拖动，旁边的坐标编辑器负责精确输入。这个分工参考 [Apple Motion 的曲线编辑](https://support.apple.com/en-mide/guide/motion/motn147476b0/mac)：拖动直观地调整形状，数值用于复现和精校；Shift 限制移动方向，细调保持相同编辑对象。[PlayStation Accessories 的配置和摇杆响应设置](https://controller.dl.playstation.net/controller/lang/en/2100005.html)则支持将响应调整与配置身份放在同一工作区。

| 操作 | 方法 |
| --- | --- |
| 选择与拖动 | 点击控制点；内部点可拖动，端点固定 |
| 精确坐标 | 双击控制点进入坐标输入；输入和响应以百分比显示，按 Enter 或“应用精确坐标”提交 |
| 细调与约束 | Alt 将拖动幅度缩小为十分之一；Shift 限制在主要移动轴；也可锁定输入或吸附 1% 网格 |
| 插入与删除 | 双击合法的空白位置，或点击“插入点”在当前段中间插点；Delete 或“删除点”移除内部点 |
| 键盘 | 左右键选择邻点，上下键按 0.1 个百分点调响应；Shift+上下键按 1 个百分点调整 |
| 撤销与取消 | Ctrl+Z / Ctrl+Y 撤销重做；一次拖动记录为一步，曲线类型和名称一起恢复；拖动时 Escape 取消整次操作 |
| 查看细节 | ＋ / － 缩放，中键平移，“适合视图”恢复完整范围；展开“全部点位”逐项选择与精校 |

蓝线表示当前曲线，灰虚线表示已保存曲线。曲线画布与原生运行程序都使用**分段线性插值**；界面不增加原生程序无法执行的贝塞尔切线。控制点必须有 2～32 个，输入与响应都严格递增，端点为 `[0, 0]`、`[1, 1]`。拖动会停在邻点之间；精确输入越界或交叉会被拒绝，不会悄悄修改成另一个数值。

曲线预设和导入导出采用固定格式，坐标按 0～1 归一化：

```json
{
  "schema_version": 1,
  "kind": "normalized_stick_response",
  "name": "训练用曲线",
  "interpolation": "piecewise_linear",
  "points": [[0, 0], [0.25, 0.1], [0.5, 0.3], [1, 1]]
}
```

导入或选择预设会复制曲线到当前配置。之后编辑当前曲线不影响预设或其他配置。格式版本、有限数值、递增顺序、点数和端点都会校验。损坏的预设会显示提示，同时保留其他可读预设。

## 独立配置怎样保存

配置的权威文档位于 `profiles/library/p_<id>.json`，格式版本为 2。它包含名称、游戏、配置字段、标准格式的曲线和创建时的快照。曲线只在这个文档中存一份；同名 TOML 是供原生程序使用的投影，自定义点会转换成 `custom_points` 字符串。

配置保存界面涉及的参数，以及导入文件中显式指定的其他原生参数。未显式写入的其他控制参数继续使用原生默认值。新建时通过当前原生加载器读取默认值，不借用全局配置中的历史覆盖值；没有原生程序时，可创建和编辑配置，使用字段默认值，但启动前仍需构建主程序。

```toml
[runtime]
game = "apex"

[gamepad.aim_response_curve]
algorithm = "custom_lut"
custom_points = "0:0;0.25:0.1;0.5:0.3;1:1"
```

原生加载器接受这样的独立文件，拒绝把它按另一个游戏启动；原有多游戏 TOML 的解析方式仍可用于显式导入和旧启动入口。重新打开 GUI 读取配置保存的曲线，不推测应该使用动态曲线。

保存先验证字段、曲线和原生 TOML，再写入 JSON 与生成的 TOML；每个文件采用同目录临时文件和原子替换。已有 JSON 在替换前备份到 `runs/desktop/profile-backups/`。外部修改配置 JSON 或生成的 TOML 会阻止保存，避免覆盖用户修改；可重新载入 JSON，或把外部编辑的 TOML 导入为新配置。完整配置编辑器先校验并写入草稿，不直接绕过配置文档写运行文件。

## 启动与运行中的修改

启动前会保存并校验配置，再核对模型文件。模型不存在时保留当前运行实例，显示修正入口。切换配置会请求旧实例正常退出，确认退出后才启动新实例；超时不会强杀或重复启动。

保存正在运行的同一份配置后，工具尝试热重载支持的参数。实际生效状态以原生确认结果为准：支持项提示已应用；等待视觉帧时明确显示尚未全部生效；结构性修改提示需要重启，避免宣称部分修改已全部应用。请求完成必须同时匹配运行 PID 和请求 ID。

| 修改 | 生效方式 |
| --- | --- |
| 辅助力度、腰射 AI 倍率、学习开关、压枪、开火绑定 | 原生支持的路径可热重载 |
| 友方判断、目标高度 | GPU Vision Service 支持的路径可热重载 |
| 曲线、模型、捕获与输入尺寸、性能档位、手柄与日志等结构项 | 保存后按原生提示重启 |

Fusion 在“运行反馈”独立打开和关闭。启动主程序不自动打开 Fusion，关闭 Fusion 不停止主程序；首次打开需主程序已经初始化。关闭 GUI 也不会停止主程序或 Fusion。

响应学习表和导出 JSON 保留四个区域的有效响应、学习响应、置信度和样本数。单位为 `px / (有效摇杆 × 秒)`，它是控制器内部估计，不是独立游戏曲线测量。导出文件位于 `runs/desktop/learning/`。没有原生数据时显示空态。

## 界面响应与控件生命周期

切换工作区时，窗口保留已经创建的控件，只切换可见页面；切换配置时，将该配置的草稿绑定到同一组输入控件。四个工作区按首次访问创建，高级参数组按首次展开创建，之后都复用。页面数不会随着切换次数或配置数量增长，配置草稿与曲线撤销历史仍由各自的配置持有。关闭窗口才释放控件、变量绑定和后台状态观察器。

这个生命周期解决了切页停顿的直接原因：原实现每次销毁整页，重新创建控件、布局和滚轮绑定。900×740 的真实 Tk 窗口中，修复前 16 次切页的耗时中位数为 137.22 ms，修复后相同操作为 44.05 ms。两次都启用了 cProfile，统计从调用切页到 Tk 处理完刷新事件；首次创建页面也计入样本。首次进入工作区仍有初始化开销，修复后这组样本的最大值为 140.43 ms。

拖动曲线时，画布更新已有线段和控制点，坐标轴等未变化的图形不重复创建或更新。配置栏只在名称、选择或修改标记变化时重绘；点位表关闭时不刷新表格。拖动和参数输入也不查询运行进程。原实现每次编辑都会同步检查运行状态，文件系统或运行进程响应变慢时，会阻塞 Tk 的事件处理。[Python 的 Tkinter 文档](https://docs.python.org/3/library/tkinter.html#threading-model)说明了这一约束：耗时事件处理会推迟其他界面事件。

运行反馈现在由一个后台观察线程读取，约每 500 ms 发起一次观察，最多保留一个待处理请求。线程不访问 Tk 对象，界面线程每 50 ms 接收结果并更新控件。保存、启动等操作完成后，窗口丢弃在操作完成前开始读取的旧结果，再请求新状态，防止旧观察结果覆盖新的重载反馈。保存和启动仍在操作执行时检查真实实例身份，不以界面显示状态作为运行授权。

可用 `python/tools/benchmarks/desktop_ui_interactions.py --profile --output output/desktop-ui-performance/check.json` 复测，运行前设置 `PYTHONPATH=python`。脚本只使用临时配置库，不启动原生输出；记录每次交互耗时，包括 Tk 刷新。修复后参数修改中位数为 2.68 ms，曲线编辑为 5.15 ms。这些数值受系统负载影响，表示界面交互耗时，不能换算成游戏帧率或证明 Aim 性能提升。

## 本次交付与验证范围

验证使用真实 Tk 控件、临时配置库和生产原生加载器。截图脚本位于 `runs/desktop-ui-design-20261004/capture_native_gui.py`，截图位于 `output/desktop-ui/`。窗口按 900×740、840×680 检查密度与主要操作；原生测试检查独立游戏配置、曲线读取、随机曲线映射、热重载和手动透传。

测试不启动游戏或向实际手柄输出输入。程序启动调用通过替身检查配置路径与 ID，原生配置读取和相关原生测试实际执行；实时游戏中的模型初始化、连接、热重载与手感仍需使用实际环境核对。
