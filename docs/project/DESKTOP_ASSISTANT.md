# 手柄助手：配置工作室

手柄助手现在以独立配置为编辑对象。一份配置保存自己的模型、辅助参数和响应曲线，游戏在创建时确定。切换配置只改变正在编辑的对象；右上角的运行状态始终指向实际运行的实例，点击“切换并启动”才会切换运行配置。

双击项目根目录的 **`启动助手.vbs`** 打开桌面 GUI。界面仍使用 Python 自带 Tk，滑杆、开关和选择菜单由轻量控件绘制，不需要安装新的 GUI 框架。

## 第一次使用

新配置库不会自动展示历史场景，也不会改写 `config.toml`。

1. 点击“＋ 新建”，填写名称并选择游戏。Apex、BO3 默认使用线性曲线，通用 / COD 使用原生 COD 动态曲线。
2. 在“设备与运行”选择 TensorRT `.engine` 模型。新配置的模型路径留空，避免误用此前训练产生的模型。
3. 在“参数调校”调整力度，或在“响应曲线”拖动控制点。点击“保存修改”写入配置；点击“启动配置”保存并启动。

需要使用已有参数时，从“配置管理 → 导入配置”选择原来的 TOML。导入时指定游戏，工具将基础值与该游戏的覆盖值解析成独立快照，原文件保留。旧版 `profiles/*.json` 元数据也可显式导入其同名 TOML。新版完整配置 JSON 自带游戏身份，导入时保留它并创建新 ID。

“配置管理”还提供复制、重命名、导出、重新载入和恢复创建时的参数。复制包含当前有效草稿，形成独立配置；重命名保留 ID；恢复创建时的参数先进入草稿，保存后才写入文件。重新载入会询问是否丢弃尚未保存的草稿。

## 五个工作区

| 工作区 | 常用操作 |
| --- | --- |
| 参数调校 | 两列显示首次瞄准与腰射、识别目标、开火与压枪，共 12 项；高级区提供手动意图、开火节奏和四个响应初值 |
| 响应曲线 | 切换内置曲线、拖点、逐点精调、撤销重做、预设与 JSON 导入导出 |
| 范围与跟随 | L2 阈值、首次瞄准范围与瞄点、持续跟随范围及纠偏；拖动目标查看纠偏方向和力度示例 |
| 设备与运行 | 模型、捕获与模型输入尺寸、手柄、检测帧率设置、日志开关、完整配置编辑和重启 |
| 运行反馈 | 原生运行与连接状态、整体与 Aim 帧率、Aim 时长和帧数、四个响应学习区域、Fusion 开关、运行日志与学习数据导出 |

参数页支持按名称或字段路径查找，匹配响应初值时会展开高级项。右键参数或按 Shift+F10 可查看范围与恢复该项创建时的值。直接输入保留小数精度；非法输入留在原处、显示错误并阻止保存。切页和切换配置保留各自的草稿，互不覆盖。

滚轮在输入框、滑杆和关闭的选择菜单上用于滚动页面，不修改参数。鼠标经过控件不会取得焦点。选择菜单的上下键只移动候选，点击或 Enter 提交；Escape、Tab 或点击外侧取消，关闭后归还焦点。

“开火与压枪 → 开镜后禁火（ms）”设置实体 L2 按下后，自动开火必须等待的时间。范围为 0～5000 ms，允许输入小数，默认 0 表示不增加等待。计时从实体开镜输入首次激活开始，目标晚出现或 L2 继续按深不会重新计时；松开并再次按下后开始新窗口。该窗口只阻止自动开火，手动开火、手柄透传和瞄准辅助保持即时响应。它与自动连发的两次脉冲之间的间隔分别控制不同阶段。按住 L2 时热加载新时长，以本次按下时刻计算新截止时间。

展开“高级：意图、开火与响应”可以设置 AI 怎样理解手动摇杆。默认忽略阈值为 `0.15`、完整阈值为 `0.30`，分别表示 15% 和 30%。逐轴力度不超过忽略阈值时，手动纠偏意图权重为 0；两阈值之间用平滑曲线增加权重；达到完整阈值后权重为 1。这个权重供原有目标纠偏和辅助仲裁使用，实体摇杆仍原样透传，鼠标策略独立。两个阈值必须满足 `0 ≤ 忽略阈值 < 完整阈值 ≤ 1`。降低边界会更早采纳手动意图，提高边界会让 AI 在更大输入范围内继续主导。

同一高级区还提供“自动连发周期（ms）”和“单次按住时长（ms）”，默认分别为 100、30。周期是两次自动按下之间的时间：默认每秒最多 10 次，每次按住 30 ms，随后松开 70 ms。两项范围为 1～5000 ms，按住时长不能超过周期。修改阈值、禁火窗口或连发节奏可热加载，不清空已有的响应学习；新的阈值从后续控制 tick 生效，连发节奏变更会取消旧自动脉冲，再按新设置调度。

## L2 与 ADS 触发范围

瞄准辅助有两个连续阶段：ADS Snap 首次抓取，BodyLock 持续跟随。两个阶段统一使用横向、纵向 AI 输出上限，界面为 0～100%，文件为 0～1。100% 表示允许使用满幅，0% 表示该轴不输出辅助；它不是倍率，也不承诺实际输出始终等于上限。响应时间单独设置，改变上限不会改变未触顶的位置纠偏需求。参数页提供 ADS 上限的快捷编辑，范围页显示完整阶段参数，两处共享同一份草稿。

“范围与跟随”把按键力度和空间范围放在一起调校。L2 超过“预搜索阈值”后提前搜索目标，默认 `0.05`，即 5%；该预备阶段本身不授权瞄准辅助。达到“开镜辅助阈值”后允许 ADS snap 和后续跟随，默认 `0.80`，即 80%，仍需满足目标及手动仲裁条件。它按扳机力度推定开镜就绪，不确认游戏开镜动画是否完成，自动开火还要满足原有的禁火、瞄准稳定等条件。预搜索阈值可设为 0～0.95，开镜辅助阈值必须更高，两项都可以热加载。实体 L2 的输出不被这些阈值改写。松开采用既有滞回：力度降到 `max(0, 预搜索阈值 − 0.02)` 或以下，连续三次采样后退出，避免边界抖动反复开关。手动开火等其他已配置的激活路径仍独立生效。

左侧同图显示蓝色 ADS 拾取圈和紫色 BodyLock 跟随圈，直接比较两者大小。选择直立、蹲姿或宽矮外形，高度输入只调整示例框，例如 25 表示目标框占捕获画面高度的 25%，不保存为配置。拖动目标，观察瞄点是否分别进入两个圈：白色十字是准星，蓝点是目标瞄点，绿色区域是可用瞄准区域。修改右侧半径即时重绘对应圆圈，图例显示实际放宽后的数值。新一次 ADS 拾取采用：

`有效半径 = 基础半径 × (1 + 0.75 × clamp(目标框高度 / 实际帧高度, 0, 1))`

默认基础半径为 150 px；目标高度占帧高 10%、25%、50% 时，半径分别为 161.25、178.125、206.25 px。图示使用当前配置的捕获宽高，单位为捕获帧像素；动态视野的实际帧尺寸可能不同。基础半径同时影响视觉选择和控制器，因此保存后需要重启，草稿预览立即更新。

外形规则来自目标框：高度 / 宽度小于 0.65 时使用宽矮瞄点，其余使用普通瞄点。直立和蹲姿示例使用同一普通比例，宽矮示例使用独立比例。这里没有骨骼姿态识别；示例名称帮助比较框形。蓝点是瞄点，绿色区域是原生回退瞄准区域，白色十字是准星。两种瞄点比例可热加载。进入触发圈后，识别结果、友方判断、身份及结果时效等原有条件仍需满足。

图示同时显示尺寸与外形是否允许新目标拾取，或仅允许继续跟踪。新目标高度至少达到帧高的 8%、面积达到帧面积的 0.3%；继续跟踪对应 6% 和 0.2%。普通框高宽比要求 0.85～4.5，宽矮框要求 0.30～4.5。高度和面积两项都要满足，因此很小的框即使位于圆内，也不会显示为尺寸允许新目标。这里沿用原生过滤规则，没有添加新的运行门槛。

“试按 L2”已经移除。右侧两个实际 L2 阈值继续用 0～1，`0.05 = 5%`、`0.20 = 20%`。范围图只读当前配置草稿，不向手柄输出，也不是实时游戏叠加层。

右侧保留 L2 预搜索与启用阈值，均按扳机行程百分比输入。选择 ADS 时显示基础抓取半径、横纵输出上限和基准响应时间；选择 BodyLock 时显示基础跟随半径、横纵输出上限和横纵响应时间。瞄点位置在参数页设置，明确表示距目标框顶部的百分比。

BodyLock 跟随半径保存为 `gamepad.bodylock.activation_range_px`，原生默认 150 px。完整目标框的跟随范围采用相同的大小放宽公式，基础值不低于当前 ADS 完成距离。当前目标瞄点超出范围时，BodyLock 不输出辅助，目标身份保留；这不等于丢弃识别结果。只有标记延续时不增加目标大小加成，图下单独标出基础范围。

BodyLock 的横纵响应时间分别保存为 `gamepad.bodylock.response_time_x_ms` / `response_time_y_ms`，范围 5～1000 ms，新配置默认为 180 / 130 ms。它们是位置纠偏的规划时间：越短越急，不是等待时间，不承诺在该时间内到达。旧纠偏距离与力度只在配置读取边界换算一次，求解器不再用当前输出上限反推响应时间。

两个阶段的输出上限都保存为 `gamepad.<ads|bodylock>.output_limit_x` / `output_limit_y`，范围 0～1；ADS 默认为 100% / 100%，BodyLock 为 30% / 42%。上限和响应时间均可热加载并保留响应学习与目标生命周期。最终 AI 输出还受目标可信度、横纵联合限幅和手动权限约束；上限不限制用户原始手动输入。

预览顶部直接选择“① ADS Snap · 抓取 / ② BodyLock · 跟随”，右侧参数与结果随阶段一起切换。参数焦点和编辑不会偷偷切换阶段。默认只显示当前范围圈，勾选“对比两圈”可在同一位置比较；“居中 / 圈内 / 圈外”按钮与拖动只改变示例位置。ADS 页内可直接调整首次抓取输出上限和基准响应时间。阶段切换不修改配置，也不切换原生控制器的运行模式；右侧示例基于静止目标和线性响应，不是实时输出。

图中的十字标为“准星”，蓝点标为“目标瞄点”，当前阶段的范围圈突出显示。下方展示当前阶段、输入参数、目标位置、两轴输出方向及力度上限。ADS 模式读取首次抓取横纵输出上限和基准响应时间；目标大小参与原生的收敛尺度计算，上方目标沿用原生的纵向修正。超出拾取圈或不满足新目标条件时显示不能新拾取、零辅助。跟随模式读取横纵响应时间与输出上限，假定目标已经选中；即使目标位于 ADS 拾取圈外，仍可在跟随圈内继续纠偏。超出跟随圈或尺寸不足时显示停止。横纵共同达到椭圆限制时说明两轴不能各自用满；已经对齐的静止目标不需要位置纠偏。另一阶段参数尚未输入完整时，只隐藏其比较圈，不用默认值替代草稿，也不阻止当前有效阶段的预览。

两阶段动作示例都假定目标静止、线性响应、标定值 500 且权限完整；跟随示例额外假定目标已选中。它不是实时控制数据、性能统计或实测游戏轨迹。原生只读入口提供 300 组实际 ADS 求解器结果、100 组 BodyLock 结果与另 40 组跟随位置需求参考。ADS 校验覆盖目标大小、上下左右方向、零力度、力度上限和时间截断；跟随核对两轴方向、共同限幅、零力度和 1 px 等情况。规则在后台读取一次，编辑和模式切换只更新现有 Canvas 图元，不启动进程、不读写文件。原折线图、固定对比设置 18 和计算得到的“响应时间”已从主界面移除。

ADS 的基准响应时间为 60～350 ms，默认 135 ms；规范化手柄参数不再按目标大小或向上方向隐式缩短时间。它与抓取生命周期时限分开，修改响应时间不延长目标等待或独占预算。BodyLock 使用独立的横纵规划时间。学习到的游戏响应参与需求换算，但不会改变所设置的时间。

历史参数换算仍由普通原生诊断 `BaseBodyLock.feedback_distance_delay_noise_sweep` 覆盖；它保留延迟、噪声、不同曲线与移动目标的数值场景，不作为新参数的交互说明或实战验收。新参数另有两组独立随机种子的 160 条短、长输入流，共 202240 个采样时刻，逐例记录输出椭圆边界与固定响应时间。它检查数值不变量，不模拟完整游戏。

几何常量由原生程序的只读入口 `--describe-ads-geometry` 提供，入口在模型、设备和输出初始化之前返回。界面使用这些常量绘图，检查将大小及临界外形的 35 组结果与原生输出逐项对照，避免另写一套不一致的规则。

## 手动曲线编辑

画布负责选点和拖动，旁边的坐标编辑器负责精确输入。这个分工参考 [Apple Motion 的曲线编辑](https://support.apple.com/en-mide/guide/motion/motn147476b0/mac)：拖动直观地调整形状，数值用于复现和精校；Shift 限制移动方向，细调保持相同编辑对象。[PlayStation Accessories 的配置和摇杆响应设置](https://controller.dl.playstation.net/controller/lang/en/2100005.html)则支持将响应调整与配置身份放在同一工作区。

| 操作 | 方法 |
| --- | --- |
| 选择与拖动 | 点击控制点；内部点可拖动，端点固定 |
| 精确坐标 | 双击控制点进入坐标输入；输入和响应以百分比显示，按 Enter 或“应用精确坐标”提交 |
| 细调与约束 | Alt 将拖动幅度缩小为十分之一；Shift 限制在主要移动轴；也可锁定输入或吸附 1% 网格 |
| 插入与删除 | 双击合法的空白位置，或点击“插入点”在当前段中间插点；Delete 或“删除点”移除内部点 |
| 键盘 | 左右键选择邻点，上下键按 0.1 个百分点调响应；Shift+上下键按 1 个百分点调整 |
| 撤销与取消 | Ctrl+Z / Ctrl+Y 撤销重做；一次拖动记录为一步，曲线类型和名称一起恢复；拖动时 Escape 取消整次操作 |
| 查看细节 | ＋ / － 缩放，中键平移，“适合视图”恢复完整范围；展开“全部点位”逐项选择与精校 |

蓝线表示当前曲线，灰虚线表示已保存曲线。曲线画布与原生运行程序都使用**分段线性插值**；界面不增加原生程序无法执行的贝塞尔切线。控制点必须有 2～32 个，输入与响应都严格递增，端点为 `[0, 0]`、`[1, 1]`。拖动会停在邻点之间；精确输入越界或交叉会被拒绝，不会悄悄修改成另一个数值。

曲线预设和导入导出采用固定格式，坐标按 0～1 归一化：

```json
{
  "schema_version": 1,
  "kind": "normalized_stick_response",
  "name": "训练用曲线",
  "interpolation": "piecewise_linear",
  "points": [[0, 0], [0.25, 0.1], [0.5, 0.3], [1, 1]]
}
```

导入或选择预设会复制曲线到当前配置。之后编辑当前曲线不影响预设或其他配置。格式版本、有限数值、递增顺序、点数和端点都会校验。损坏的预设会显示提示，同时保留其他可读预设。

## 独立配置怎样保存

配置的权威文档位于 `profiles/library/p_<id>.json`，格式版本为 2。它包含名称、游戏、配置字段、标准格式的曲线和创建时的快照。曲线只在这个文档中存一份；同名 TOML 是供原生程序使用的投影，自定义点会转换成 `custom_points` 字符串。

配置保存界面涉及的参数，以及导入文件中显式指定的其他原生参数。未显式写入的其他控制参数继续使用原生默认值。新建时通过当前原生加载器读取默认值，不借用全局配置中的历史覆盖值；没有原生程序时，可创建和编辑配置，使用字段默认值，但启动前仍需构建主程序。

```toml
[runtime]
game = "apex"

[gamepad.aim_response_curve]
algorithm = "custom_lut"
custom_points = "0:0;0.25:0.1;0.5:0.3;1:1"
```

原生加载器接受这样的独立文件，拒绝把它按另一个游戏启动；原有多游戏 TOML 的解析方式仍可用于显式导入和旧启动入口。重新打开 GUI 读取配置保存的曲线，不推测应该使用动态曲线。

保存先验证字段、曲线和原生 TOML，再写入 JSON 与生成的 TOML；每个文件采用同目录临时文件和原子替换。已有 JSON 在替换前备份到 `runs/desktop/profile-backups/`。外部修改配置 JSON 或生成的 TOML 会阻止保存，避免覆盖用户修改；可重新载入 JSON，或把外部编辑的 TOML 导入为新配置。完整配置编辑器先校验并写入草稿，不直接绕过配置文档写运行文件。

## 启动与运行中的修改

## 不开日志查看帧率

启动更新后的原生程序，打开“运行反馈”，即可查看应用平均 FPS、Aim 平均 FPS、近 5 秒 Aim FPS，以及 Aim 累计时长和帧数。旧进程需要重启才能提供新增的内存通道。无需启用“记录性能摘要”或其他性能日志；为了减少日志开销，可在设备与运行设置中关闭不需要的日志，再按提示重启。

这些数值计算的是控制器实际消费的新视觉结果。Aim 按实体开镜状态计时，开镜期间丢目标或没有新帧的时间也计入；重复读取同一结果不增加帧数。平均值用累计帧数除以累计时间，最近值用最新完成的 100 ms 边界之前、最多 5 秒内的 Aim 帧数除以 Aim 时长。它不能代表游戏画面呈现 FPS、控制循环频率或推理耗时的倒数。尚未开镜时显示 `—`；开镜且无新帧时显示 `0.0`。

## 界面响应与控件生命周期

切换工作区时，窗口保留已经创建的控件，只切换可见页面；切换配置时，将该配置的草稿绑定到同一组输入控件。五个工作区按首次访问创建，高级参数组按首次展开创建，之后都复用。页面数不会随着切换次数或配置数量增长，配置草稿与曲线撤销历史仍由各自的配置持有。关闭窗口才释放控件、变量绑定和后台状态观察器。ADS 图示也更新已有画布对象，原生规则在后台读取；拖动不查询进程、不创建新图形。

高级入口放在两列常用参数下方，左对齐并单独占一整行；展开内容在其下方分为两列。按钮用箭头表示内容可见性，不修改运行开关。滚动区域始终至少等于可视窗口高度，内容不足一页时固定在顶部；折叠、搜索和窗口缩放会重新计算范围。它修正了短页面向上滚动露出空白的原因，不靠禁止滚轮掩盖偏移。

这个生命周期解决了切页停顿的直接原因：原实现每次销毁整页，重新创建控件、布局和滚轮绑定。900×740 的真实 Tk 窗口中，修复前 16 次切页的耗时中位数为 137.22 ms，修复后相同操作为 44.05 ms。两次都启用了 cProfile，统计从调用切页到 Tk 处理完刷新事件；首次创建页面也计入样本。首次进入工作区仍有初始化开销，修复后这组样本的最大值为 140.43 ms。

拖动曲线时，画布更新已有线段和控制点，坐标轴等未变化的图形不重复创建或更新。配置栏只在名称、选择或修改标记变化时重绘；点位表关闭时不刷新表格。拖动和参数输入也不查询运行进程。原实现每次编辑都会同步检查运行状态，文件系统或运行进程响应变慢时，会阻塞 Tk 的事件处理。[Python 的 Tkinter 文档](https://docs.python.org/3/library/tkinter.html#threading-model)说明了这一约束：耗时事件处理会推迟其他界面事件。

运行反馈现在由一个后台观察线程读取，约每 500 ms 发起一次观察，最多保留一个待处理请求。线程不访问 Tk 对象，界面线程每 50 ms 接收结果并更新控件。保存、启动等操作完成后，窗口丢弃在操作完成前开始读取的旧结果，再请求新状态，防止旧观察结果覆盖新的重载反馈。保存和启动仍在操作执行时检查真实实例身份，不以界面显示状态作为运行授权。

可用 `python/tools/benchmarks/desktop_ui_interactions.py --profile --output output/desktop-ui-performance/check.json` 复测，运行前设置 `PYTHONPATH=python`。脚本只使用临时配置库，不启动原生输出；记录每次交互耗时，包括 Tk 刷新。修复后参数修改中位数为 2.68 ms，曲线编辑为 5.15 ms。这些数值受系统负载影响，表示界面交互耗时，不能换算成游戏帧率或证明 Aim 性能提升。

GUI 测试和交互耗时脚本现在在独立 Windows 桌面运行，不切换你正在使用的桌面。真实窗口、菜单聚焦和键盘事件仍被检查；直接在当前桌面启动 Tk 测试会报错，提示使用隔离入口。统一命令为 `D:\env\python\python.exe python/tools/check_app.py`；参数 `--scope config` 只做快速配置检查，`--scope gui` 只运行隔离桌面检查，`--build` 先构建原生 Release。增加参数与验证方法见 [配置项与检查工作流](CONFIGURATION_AND_CHECKS.md)。

## 2026-10-06 数值一致性与 AI 输入死区

“范围与跟随”新增 **AI 输入死区**，默认 3%，可填 0～100%。在 AI 规划、整形、腰射衰减之后，送入手动/AI 合成器之前逐轴处理：绝对值 ≤ 阈值归零，超过阈值原值通过。0% 关闭过滤；100% 过滤所有规范化 AI 输入。参数支持保存后热加载，不重置目标身份或响应学习。实体摇杆与独立压枪不经过此过滤器。后续手动权限仲裁仍可衰减 AI，因此最终合成输出不承诺至少 3%。

近准星大输出的根因：原请求只按误差、响应速度和规划时间换算，非线性逆曲线还可能继续放大它。现在 ADS 与 BodyLock 共用位置策略：使用当前阶段实际检测范围 R、到瞄点距离 d，在用户曲线之后用 `sqrt(clamp(d/R,0,1))` 限制位置纠偏预算，并受横纵输出上限约束。范围来自原生协调器；进入人物框不会结束位置任务。

参数 → 高级 → 位置收敛提供“低速参考力度”（默认 20%，0～100%，支持热更新）和“近点收尾半径”（默认 2 px，1～64 px，重启生效）。低速参考用于追赶，接近实际瞄点时允许连续降到此值以下；刹车预判可抵消位置推力。收尾半径不再是 BodyLock 硬归零边界，ADS 仍用它判断抓取完成。可信移动补偿持续跟随，最终 AI 输出仍受显式输入死区和手动权限约束。最新模拟与验证见 [配置说明](CONFIGURATION_AND_CHECKS.md)。

ADS 完成与输入状态机使用同一瞄点距离。旧配置明确设置的 ADS 完成距离会显示为新字段的迁移值；不会把已有值暗中改成 2 px，也不会覆盖个人配置。静态线性预览与原生计算逐项对照，真实运动补偿、设备延迟不包含在静态图示中。

ADS 规范化响应时间现在直接进入位置求解，不再因目标大小或向上方向缩短。BodyLock 基础范围若小于 ADS 完成距离则拒绝保存/启动，避免原先静默抬高。捕获和模型输入四项尺寸的界面下限统一为原生支持的 32。跟踪器旧配置中的瞄点比例/观测年龄和输入手柄编号越界也明确拒绝，不静默截断。
