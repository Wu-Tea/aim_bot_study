# 手柄助手：Profile Manager

手柄助手围绕一份可命名的配置来使用：选择 Profile，确认游戏、模型与曲线，调整参数，再启动。双击仓库根目录的 `启动助手.vbs` 打开界面。GUI 使用已有的 Python 与标准库 Tk/ttk，原生控制器仍由 `native/build/Release/cod_native_runtime.exe` 独立运行。

## 从选配置到开始游戏

顶部是横向配置库。当前 Profile 有明显的焦点边框，选中后下方显示它的名称与设置；蓝点表示该 Profile 有未保存的修改。配置库获得键盘焦点后，可用左右方向键切换。

界面参考 PS 主机的配置选择与集中操作逻辑：先突出当前对象，再进入它的操作，常用动作持续可见。深色背景、浅色焦点与白色主按钮用来区分当前选择和下一步。设计参考：[Sony 对 PS5 用户体验与 Control Center 的介绍](https://blog.playstation.com/2020/10/15/first-look-playstation-5s-next-generation-user-experience/)。

日常使用顺序如下：

1. 点击“新建配置”，填写名称并选择游戏场景；也可以复制当前配置。新建以现有配置为初始模板，复制会包含当前未保存的修改。
2. 在“配置概览”选择模型和工具响应曲线。界面显示主程序与模型是否就绪。
3. 在“辅助参数”调整开镜、跟随、目标点、开火和压枪。常用力度同时支持滑杆和精确输入。
4. 在“响应曲线”直接编辑曲线，或选择、导入已有曲线预设。
5. 保存并启动。运行中支持的参数可保存后应用；曲线、模型和运行条件的修改需要重启。

底部的启动、保存、停止和修改反馈位于滚动区外。窗口默认 1120×840，最小 840×680；小窗口的曲线图会缩小高度，参数区可以滚动。键盘聚焦屏幕外的输入项时，工作区自动滚动到它。

“运行设置”管理此 Profile 的手柄连接、日志、捕获和性能条件。“学习与诊断”集中显示响应估计、Fusion、数据导出和运行日志。响应初值、死区补偿与性能细节默认收起，可按需展开。

## 每份 Profile 保存自己的参数

新配置存储在 `profiles/`，文件名使用稳定 ID，名称可以修改。配置包含创建时的完整参数快照，因此同样用于 Apex 的两份配置也可以拥有不同模型、曲线、辅助力度和运行条件；之后改动另一份 Profile 不会改变它。

```text
profiles/
  p_<稳定 ID>.json       # schema_version、名称、游戏场景
  p_<稳定 ID>.toml       # 完整原生配置快照
  curves/
    <稳定 ID>.json       # 可复用的曲线预设
```

现有 `config.toml` 中的 COD、Apex 与 BO3 配置作为模板显示。模板首次修改后通过界面保存，会生成独立 Profile，原文件保留。使用“复制当前配置”也能将模板转成独立配置；模板不能直接重命名或通过新界面的源文件编辑器改写。未修改模板时可以按原设置启动。

切换 Profile 会暂存各自的草稿，保存只提交当前 Profile 的草稿。草稿没有跨应用重启持久化；关窗时只要任何 Profile 仍有草稿，都会询问是否放弃。配置选择在切换时立即原子保存到 `runs/desktop/ui.json`，不依赖正常关窗。重新打开窗口时优先接管受管理的运行实例，否则恢复最近的 Profile。

游戏场景与正在运行的配置分别显示。仅选择另一个 Profile 不切换运行实例；点击“切换并启动”后，先正常停止旧实例，再启动新文件。同一游戏的两份 Profile 按配置文件路径核对身份，避免保存第一份配置却向第二份发送重载。

## 曲线可以直接拖动

曲线的横轴为归一化摇杆幅度，纵轴为归一化响应。虚线是线性响应，实线是当前曲线；这些点描述控制器使用的响应模型，并不意味着已经独立测量了游戏摄像机响应。原始手动输入继续按原样透传。

- 鼠标拖动控制点，改变输入位置与响应。
- 双击曲线区域添加控制点；Delete 或右键删除选中的内部点。
- 左右方向键选择点，上下方向键以 0.01 微调响应。
- “线性模板”生成线性控制点，“COD 动态模板”使用原生版本化 LUT 的原始点。
- “保存预设”写入曲线库；“导出”写入所选 JSON 文件，“导入”校验并添加曲线，当前配置采用其副本。

起止端点固定为 `(0,0)` 与 `(1,1)`，控制点数量为 2～32，输入和响应都必须严格递增。拖动会约束在邻居之间。这是正向和反向插值共同需要的条件：没有单调性，就不能唯一地从目标响应求回摇杆输出。

曲线预设采用统一的版本 1 格式：

```json
{
  "schema_version": 1,
  "kind": "normalized_stick_response",
  "name": "我的响应曲线",
  "interpolation": "piecewise_linear",
  "points": [[0, 0], [0.25, 0.10], [0.50, 0.30], [1, 1]]
}
```

导入会拒绝未知格式版本、非有限数值、越界坐标、重复点、非单调点和错误端点。导入或选择预设会把控制点复制到当前 Profile；之后修改曲线库不会悄悄改变已保存的配置。

原生配置使用下面的形式记录实际控制点，按相同顺序进行分段线性插值：

```toml
[games.apex.gamepad.aim_response_curve]
algorithm = "custom_lut"
custom_points = "0:0;0.25:0.1;0.5:0.3;1:1"
```

拖动先产生草稿，保存才写入配置文件。曲线修改需要重启，以免运行中的响应学习、输出映射和控制状态使用不同的曲线。内置 `linear` 和 `cod_dynamic_legacy_lut` 仍按原算法执行。

## 参数读取与保存

文件未写某个参数时，GUI 将同一份配置快照交给原生 `--dump-effective-config`，读取性能档位和原生默认值，避免显示另一套界面默认值，也避免混用外部编辑前后的文件。临时检查文件用完清理。原生程序不存在时，界面明确提示缺失字段暂用界面默认值，完成构建后应重新载入。

显式写入文件的值按文件显示。此视图不是运行中的参数快照；环境变量仍可能覆盖文件值。`linear` 不会因为重新打开窗口而被自动改成 COD 动态曲线。

游戏场景在各 Profile 内仍可继承它自己的基础值。“设为专属”允许固定一个与基础值相同的值；“使用通用”先产生恢复继承的草稿，保存时才移除对应的游戏键。该操作保留注释、其他参数与其他场景。

滑杆拖动以 0.01 为步长，直接输入保留小数精度。错误文本保留在输入框中并阻止保存，切换页面或 Profile 不会把它静默转成合法数值。

保存先校验 TOML、字段类型与范围，再由原生加载器校验全部场景。成功后将原文件备份到 `runs/desktop/config-backups/`，再原子替换。外部修改会导致保存被拒绝，需重新载入。Profile 和曲线元数据使用原子 JSON 写入；Windows 换行不会使复制的 TOML 出现重复回车。

## 运行、应用与学习数据

GUI 与主程序是独立进程。关窗后主程序继续运行，停止主程序不会关闭 GUI；控制循环不读取 GUI 状态。运行实例的记录包含配置文件路径、Profile ID、游戏、PID、创建时间和日志位置。停止通过按 PID 命名的 Windows 事件请求正常退出；超时不会自动强杀或另起实例。

| 修改 | 生效方式 |
| --- | --- |
| 开镜与跟随力度、腰射 AI 倍率、学习开关 | 支持的运行中配置可重新应用 |
| 固定压枪、手动开火绑定、自动开火输出 | 支持重新应用 |
| 友方判断、目标点高度 | GPU Vision Service 路径支持重新应用 |
| 曲线、模型、捕获尺寸与帧率、性能档位、死区补偿、手柄选择、日志 | 保存后重启 |

重载是否已应用、是否等待新视觉帧、是否需要重启，以原生确认为准。修改不支持重载的参数时，整次请求提示重启，避免部分生效。响应学习是否保留也以原生确认结果为准；界面不会把旧请求的完成当成新配置的确认。

Fusion 在“学习与诊断”单独打开与关闭。启动主程序不自动打开 Fusion，关闭 Fusion 不停止主程序；首次打开需要主程序已经初始化。学习表显示四个响应区域的生效系数、学习系数、置信度和样本数。这些值是控制器响应估计，并非独立游戏灵敏度。导出数据位于 `runs/desktop/learning/`。

旧前台启动入口和直接运行 exe 不提供完整的统一进程记录，GUI 不能完整接管；同路径实例扫描仍会阻止重复启动。“启动后识别手柄”也不等于持续实时监测连接状态。
