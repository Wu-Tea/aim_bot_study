## 代码中确实存在的中断路径，不等于本视频已证明触发

1. Vision的同身份判定使用上一人体框与当前框的IoU、中心距离及源点距离（target_selector.cpp:1601附近）。该判定本身没有按捕获间隔和已交付相机运动预测旧框。缺帧后大位移、跳跃/遮挡变形可能让仍是同一人的检测失配；没有active_match且无明确换目标意图时，resolve_active_target_transition拒绝本次选择。发现新框与确认原身份是两件事。
2. TargetCoordinator缺帧预测不仅限时32ms，还要求continuation有效、代际连续，并且预测偏移未超出上次aim_region半宽/半高。越出空间支持就可在32ms之前停止瞄准，但保留短暂身份。32/40ms是上限，不是保证持续输出时长。友军、低可靠度拒绝等还有独立限制，不能把它们全部叫作普通缺帧。
3. BodyLock仍有随人体尺寸扩展的持续范围；超出时aim_authority直接为0。实际基础配置150px，但不是固定150px即断，也不是70px权限分段与之相同。身份可仍在而输出无权限。
4. 未完成ADS若真正丢目标，AdsLifecycleReducer以TargetLost结束并标记snap_consumed。同次持续按住LT的周期不会因为重新找到目标而自动再启动一次ADS。后续BodyLock仍须通过自身范围、证据与预算条件。这是可能把短暂视觉中断变成明显行为变化的传播路径；不能在缺日志时断言此片段发生了它。

## 当前结论与后续定位顺序

当前最合理、但尚未由本次遥测证实的解释是：快速屏幕运动时追赶落后，继而触及检测/身份/空间支持边界，使输出出现离散中断，甚至影响后续ADS生命周期。不能简化成“目标速度超过某数就退出”，也不能仅由画面认定是原预算不足。

应先在有详细遥测的复现中确定第一个失去连续性的环节：新鲜人体检测是否仍在、同身份是否被接受、continuation拒绝原因、实际BodyLock范围、ADS终止原因、LT与手动输入、请求及交付输出。仅需恢复已有逐帧记录能力，不应先加新产品开关。当前配置保持未改。

若新鲜同目标连续且权限非零，应追查运动估计/相机响应与实际预算使用；若同人新鲜检测被错误当成新身份，应在Vision关联所属层处理相机/目标运动与时间一致性；若确无新鲜可用目标，保留32/40ms和原手动边界。提高权限、扩大旧坐标预测范围或延迟身份释放，都不能替代上述定位。
