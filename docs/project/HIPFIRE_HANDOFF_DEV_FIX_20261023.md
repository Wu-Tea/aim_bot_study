# 腰射甩枪接管与 ADS 倍率动态约束：dev

用户授权实施两处优化，保留手动甩枪、索敌和跟踪，并使用今日 clean 日志轨迹加入拟真、检查性能。两处已实现并构建到 dev；未提交/push，未同步 clean，未修改个人 Profile 或启动/停止用户游戏会话。

## 已证实的原因与实现

原始证据见 [日志分析](HIPFIRE_FLICK_LOG_ANALYSIS_20261023.md)：16:20:00 的快速回中使权限混合在 AI 平滑之后引发急反向，随后腰射倍率恢复到 ADS 强度也绕过平滑。这次只修这两个动态约束的遗漏，没有把响应模型推测当作已证明的运动估计故障。

- `AimDynamicsShaper::shape_ownership` 在原仲裁之后消费已授权输出。它计算当前手动到 AI 提议之间的份额，只限制增加的 AI 接管工作；份额减少立即生效，因此手动重新接管和 AI 权限撤销不等待。使用原有 rise slew / max-step 参数，在二维向量上限制新增 AI 工作；没有新定时器、配置开关或目标判断。新目标直接使用原获取流程，不继承旧目标的接管状态。无目标、显式退出和观测空隙不延续这份状态；稳定份额走直接返回路径，不重复平滑跟踪命令。AI与手动数值恰好相等时保留已有份额，避免过零时制造一次假的手动接管。
- canonical gamepad 的腰射倍率移到 AI 请求进入原平滑器之前。物理 ADS-ready 信号和 0.7/1.0 等用户配置值保持，恢复 ADS 强度经过原有变化速率约束。鼠标/legacy 仍走原倍率路径。
- 保留逐轴 15%–30% 权限的目标值、原始手动透传、显式退出、胸部参考、压枪及最终物理输出阶段。Vision 检测、选择、身份和频率未改。新增的是 AI 接管份额的动态状态，不能理解成更改手动意图阈值。

生产改动仅三文件：`native/controller_native/aim_dynamics_shaper.h/.cpp`、`native_gamepad_controller.cpp`。

## 日志轨迹与原生拟真

`tests/hipfire_flick_20261023/fixtures/` 保存八个窗口的 1,358 条去重数值样本及时间索引，约 179 KB，可随代码保存。包含手动 X/Y、LT、实际开火、目标误差/身份/人体大小、cue、请求与实际输出。原始完整窗口仍保留在 `runs/hipfire-flick-20261023/windows/`。

验证分为以下层级，不能混为实机重放：

1. **权限接管隔离复算。** 按日志将物理输入线性插值至 1 ms，使用记录的 AI 提议及原 carried-acquisition 权限公式。16:20:00 主案例的最大 1 ms 输出变化从 **0.121991 → 0.077648，减少 36.3%**；到达同一 AI 输出从窗口 t=0.796 s 到 0.798 s，延后 **2 ms**。这不是重新执行完整视觉/意图状态。
2. **真实原生链倍率回归。** 同一 `scope_regression.cpp` 分别链接未改 clean 和最终 dev 库。先建立稳定腰射工作再按 ADS；旧版一步变化 **0.300**、返回失败 2，新版 **0.064**、返回成功 0。另有恒定 -0.78 请求的 shaper 隔离试验，变化为 **0.234 → 0.064**。两者条件不同，不能混写为同一测量。
3. **八段完整原生控制链轨迹检查。** 每段各跑固定观测及三种相机平移模型，合计 32 个场景。相机响应/延迟假设分别为 900 px/(stick·s)/6 ms、1400/12 ms、2200/24 ms；用录制输出积分抵消原相机平移，再加入模拟输出的平移。实际手动轨迹保留，视觉样本时间和选中目标序列来自记录。全部场景前后首次获取 tick、拥有目标 tick 数一致，源胸部点、无目标手动透传及显式退出不变量通过。

闭环轨迹的限制：没有游戏画面、FOV/三维旋转/敌人世界运动真值；没有恢复窗口之前的控制器隐藏状态。视觉观测按 controller 样本和最近人体信息重建，未重新运行图像检测，目标身份/可见性序列由记录给定。相机参数是敏感性假设，不能把这些误差当作录像真实像素改善，更不能凭“首次获取相同”证明所有实机索敌场景不受影响。

在 24 个相机模型场景中，22 个窗口平均误差不增加，2 个高响应/高延迟压力条件增加：14:30:30 窗口 **+1.470 px**，16:20:00 窗口 **+1.376 px**。前者后半段也略增加，后者后半段减小。该均值按全窗口 tick 计，缺少有效目标的 tick 不贡献误差。完整逐场数据保留，不能只展示输出变平顺的图。

## 随机、回归与性能

- 两个独立种子 231023、981027，各 48 类 2 s/20 s 场景，共 **192 场、2,112,000 tick/版本**。使用已有原生闭环工具，包含静止、快速横纵移动、斜向/反向手动、强甩枪、cue 续跟、短缺帧、退出、压枪；固定 1575 ms 目标槽 + 50 ms 空隙。原始透传、胸部不随手动改变、32/40 ms 边界、cue 不获得开火权限等断言全部通过。
- 无手动场景前后误差差异不超过 CSV 精度 0.00001 px；常规跟随手动场景基本一致。快速反向压力条件有小幅代价：最差单场平均误差 **26.9163 → 28.1742 px（+1.2579）**，同时最大一步输出变化 **0.8920 → 0.6089**。不能承诺“所有跟踪指标零退步”。两个种子的全部场景平均误差为 85.0189→85.0416、83.2690→83.2744 px；包含刻意不理想的长时间手动压力，不是游戏命中率指标。
- 新增 Base 回归覆盖：释放接管、强手动立即收回、无目标零死区透传、新目标不继承延迟、稳定跟踪不重复平滑、X 接管不改变已持有 Y 跟踪，以及双种子共 20,000 个随机二维授权线段。真实原生 ADS 倍率回归含两个方向。旧版 scope 回归已确认失败。
- 最终 dev Release 全部构建成功；完整 **CTest 51/51**，其中 Base **480/480**（原 477 + 新增 3）。旧鼠标路径回归通过。结果 `runs/hipfire-flick-20261023/ctest-final.txt`。
- 三轮 before/after 交替测量，32 段轨迹中 `build_output` 的按 tick 加权均值：旧版 **2.13–2.39 μs**，新版 **1.96–2.12 μs**。逐场 P95 的中位数旧版 **4.10–4.65 μs**，新版 **3.65–4.05 μs**。没有测出新增耗时，不宣称性能提升；这些只覆盖离线原生 controller 计算，不含 GPU、捕获、实际手柄提交或游戏 FPS。
- 新路径为常数级运算与少量固定状态，无逐帧分配、锁、线程等待、Vision 附加搜索或降频。稳定权限直接返回，仅发生 AI 接管增长时计算二维工作长度。
