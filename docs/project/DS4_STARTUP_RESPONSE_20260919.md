# DS4 冷启动响应初值修正（2026-09-19）

用户报告前三个目标约 300 ms 的准星抖动，之后随在线学习改善。本次使用
`runs/native_perf/sessions/20260919T144400Z_25012_1` 的现有数据，未要求补录。
完整激活特征、19 次窗口及对比图见 `runs/ds4_startup_audit_20260919/`。

## 证据与边界

- 第一轮激活约 150 ms 从 ADS 转 BodyLock；约 206.9 ms 横向输出 -0.395，
  247.9 ms 变成 +0.744。该窗口横向原生输入未超过 25% 裁决区。
- BodyLock 控制器内部响应估计由首个目标约 504，后续逐渐升到约 600–700。
  这是从控制分量反推的内部模型，不能当作独立测得的游戏响应曲线。
- ADS 与 BodyLock 均在 response_confidence=0 时丢弃有效 response_scale。
  两个估计器本身已经按置信度融合初值，因此控制器再次判断置信度会忽略显式初值。
- 默认初值与旧回退值原本同为 500；这一消费缺陷并不单独证明实机抖动的根因。
  冷启动响应偏低是与日志相容的解释，650 是本配置的暂定修正，实机消抖尚未验证。

## 修正

新增 `[gamepad.ai_aim] aim_response_initial_scale`：0 继承原校准，其他有限值
接受 80..4000。当前本地 `config.toml` 设为 650；通用默认及示例仍为 0。
ADS 与通用响应估计器都从该值初始化，置信度仍为 0，在线学习与换目标保留学习
机制不变。直接鼠标模式继续使用自己的校准，不采用手柄初值。

ADS 与 BodyLock 消费有效 response_scale，包括置信度为零的初值；不存在或非有限
的响应才回退。BodyLock 的反馈时间仍以原校准定义，不随初值缩短，否则反馈力度
中的响应增大和时间缩短会相互抵消。

在相同误差、未饱和的线性位置分量上，500→650 将首帧需求乘以 500/650≈0.769。
这不是最终摇杆百分比的固定缩放：逆曲线、向量限幅与运动补偿仍各自参与计算。
没有添加延迟、预热目标次数或防抖。DS4 原生透传 0 输入死区和 AI 每轴 ±25%
裁决区维持原策略。

## 验证

冻结的 `startup_response_prior_tests.cpp` 在修改生产代码前失败：相同响应模型、
不同学习置信度的输出向量最大差异 0.0885969；修改后为 0。移除响应初值的负对照
仍有 0.0885969 差异。六组覆盖 ADS/BodyLock 与双轴正负误差。

真实 NativeGamepadController 测试验证了 ADS→BodyLock、500/650 位置需求比例、
初始置信度为零、松开瞄准后 ±0.012 原始输入透传，以及鼠标校准隔离。
另验证两个估计器仍能学习到新响应、换目标保留学习、reset 恢复初值，配置边界拒绝
NaN/Inf 与越界值。

Release 主程序、基础与功能测试已编译；Base/Feature 共 10 个套件全部通过。
`--dump-effective-config` 确认当前用户初值为 650。

回归证据在 `runs/ds4_startup_fix_20260919/`。这是控制器初值消费缺陷的
RED→GREEN 证明，**不是实机闭环回放或实机消抖验收**。下次正常启动即使用新初值。
