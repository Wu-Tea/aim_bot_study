## 使用

重开dev助手窗口，在“目标与识别”中可见“敌人标识颜色”“友军标识颜色”。默认洋红/青色，可输入带或不带 `#` 的六位HEX，保存时规范化为大写。与游戏颜色保持一致；更改后停止并重新启动助手，不能热更新。已有Profile缺少这两个字段时使用新默认值，已对当前 `p_cd8d772a4f4f4335905ab9b86e3e5741` 只读核实。

```toml
[runtime.vision]
enemy_marker_color = "#FF00FF"
friendly_marker_color = "#00FFFF"
```

本次不重新启用Off被动减速，不改变手动权限、索敌/续跟频率和控制算法；上次分析的人体框几何突变尚未修复。

## 模块职责与性能设计

`native/pipeline_contract/marker_palette.h` 为无设备依赖的配色模块。配置加载时解析HEX、检查格式/亮度/饱和度/敌我色相范围重叠，将色相范围编译为整数比较参数。拒绝无彩色、过暗或敌我范围重叠的输入；不把错误设置默默回退到默认值。

独立CueDetector、人物头顶颜色分类、cue外观模板采样和续跟使用相同的编译后规则。selector持有自己的配置，启动时向其CueDetector传递敌人规则；更换palette会清理旧身份与模板。游戏手柄及鼠标的Vision启动入口均接入配置。配置只在启动前设置，没有新增线程锁、每帧字符串解析、分配或图像扫描。

色相容差为OpenCV标度±8（普通角度±16°），敌人保持S≥120/V≥120，友军保持原先S≥80/V≥50。因此默认色相范围分别为142–158、82–98。HEX指定识别色相中心，不要求视频像素精确等于HEX；允许压缩、抗锯齿和亮度变化。自定义颜色使用无除法的定点色相判断，洋红/青色在加载时选择更简短的整数判定路径。

最初的通用判断实现实测增加selector均值约0.02–0.03ms、独立全图cue约0.4ms，未直接交付；最终为当前配色选择快速判定。保留每四行种子、完整连通域展开、按person和活动cue剪裁的区域搜索，不降低频率或改变形状/关联规则。

- 现有20:17菱形录像1945帧、22:52近身录像2038帧，共 **3983帧**。使用原解码图像和之前记录的原始person框/置信度，重新运行生产selector及独立cue；不沿用录像导出的友军/cue分类。这样隔离颜色模块，不重新估计神经网络对新配色图像的响应。

旧录像不是新配色实机素材，验证分三种：

1. 新规则读原图：检查背景撞色，原黄色cue不再应被当成新配色cue。不能把这条路径的目标数量下降记为新配色漏检。
2. 明确的合成掩码对照：按冻结的旧颜色分类，将旧绿色变青色、旧黄色变洋红，其他像素保持；同时移除两边旧红色，避免把旧版两个敌人色相身份合并成一个的语义变化。背景也会被重着色，所以它只用于压力/连续性和阶段计时，不代表游戏新颜色截图。
3. 两个真实人物局部标记对照：20:17的120、864帧，分别仅修改头顶已确认的24×24菱形附近黄色像素（143/130个像素），保留绿色树叶和其余背景，保留像素饱和度/亮度。改洋红后均能关联person并在person漏检时同身份cue续跟；改青色后均被正确判为友军、无目标权限。原绿色背景不再触发旧友军过滤。

单敌色掩码对照中，近身录像4596个独立cue几何全部一致；4帧weak-person瞄点不同，重着色改变了用于图像运动匹配的纹理，并非可声称输出逐帧一致的实验。菱形片段旧5109/新5130个cue，18帧几何不同，1帧目标来源不同：978帧原图本来就有青色范围像素，触发新友军规则，直接person变为cue_hold。换色仍不能彻底消除“头顶区域同色背景被算作友军”的限制；本轮没有额外修改该判断算法。初始“黄+红一起变洋红”对照产生更多身份差异，保留产物但不作为等价性判断。
