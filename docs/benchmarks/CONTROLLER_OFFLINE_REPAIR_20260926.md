# 手柄过冲离线修复：已修问题与未通过项

本轮修复了一个明确的高频观测缺陷，并补齐了模拟器的 DS4 回执对齐。**完整的过冲、抖动和摆荡修复尚未通过离线验收。** 响应/延迟校准和位置预测虽能消掉固定静止案例的摆荡，但会造成其他场景退化，均已撤回。当前没有替换用户运行的 runtime，也没有提交这些实验。

用户已明确先完成离线工作，实战稍后安排。这里的未通过项是离线算法问题，不是等待用户提供实战录像。

## 已修：视觉越快，运动估计和学习反而停止

`NativeGamepadController` 每收到一帧就覆盖上一帧的时间和坐标。响应学习需要至少 5 ms 的观测区间，运动估计需要至少 4 ms；当连续帧都比这个区间短时，每次差分都被拒绝，下次又从最近一帧开始，永远积累不出有效观测。

改动只放在源观测区间的管理处：短区间继续累积，达到学习器已有的最短区间后才前移时间和位置基准。帧 ID 仍逐帧消费，整条控制链仍逐 tick 执行，没有降低控制频率，没有新增控制 owner，也没有修改原生输入死区或 15–30% 的人工权重曲线。

两个回归直接调用生产 controller、composer 和发送回执入口。它们使用脚本确定的实际相机命令，分别验证相机运动抵消和响应学习；这不是把控制器提案接入游戏反馈的完整闭环。

| 新鲜视觉频率 | 修复前运动估计 | 修复前响应学习 | 修复后 |
|---|---|---|---|
| 100 / 160 / 200 Hz | 有效 | 有效 | 保持有效 |
| 250 Hz | 有效 | 停在初值 500、置信度 0 | 学到约 800 |
| 320 / 500 / 1000 Hz | 后段有效帧数为 0 | 停在初值 500、置信度 0 | 运动估计和学习均恢复 |

学习探针的真实响应为 800；修复后的 14 个轴向/频率组合误差最大约 0.087，28 个关闭学习或开火的反事实仍停在初值、置信度为 0。运动探针另有 14 个组合，后 75% 时间内的每个 BodyLock 观测帧都有效，静止世界运动残差小于 0.1 px/s。相同测试在旧代码上有两项失败，修复后通过。

**这个缺陷不能解释稳定 160 Hz 下的全部摆荡。** 它修复的是高频时证据被饿死的因果问题，不应扩大成对全部实战现象的解释。

## 补齐模拟器：算法和游戏必须看到同一个 DS4 指令

随机扫描器原来将浮点输出量化成 DS4 字节后交给模拟游戏，但 controller 的便捷调用入口已经把量化前的浮点值记为发送成功。现增加 `--quantized-receipt 1`，用实际 DS4 字节解码值覆盖同时间戳的回执，与此前已修改的 native runtime 发送路径一致。旧模式保留用于重跑冻结的历史 RED，报告明确记录 `receipt`，两种模式不能混为同一基线。

这个修正会改变事故表现，却没有消除失配问题。固定案例原先四方向穿越次数为 108 / 110 / 118 / 83；使用 DS4 解码回执后为 108 / 110 / 118 / 0，前三个方向仍失败。不能继续引用第四个方向的旧结果来证明真实回执路径也有同样的摆荡。

## 未通过：参数失配怎样进入跟随解算

固定案例说明了传播路径：算法假定的相机响应和生效时间不准确，抵消自身视角运动时留下残差，残差进入总运动补偿，再通过延迟输出反馈回来。它证明这组失配足以造成摆荡；这些模拟参数没有被独立标定为 Warzone/Zombie 的真实参数。

本轮拆开验证了历史指令位置预测、原始屏幕速度预测、联合位置/速度估计、延迟识别和响应识别。以下是代表性结果，不能据此挑选生产版本：

| 候选 | 固定静止 RED | 产品回归 | 16 包多目标矩阵 |
|---|---|---|---|
| 持续使用历史指令预测位置 | 通过 | 通过 | 16 包存在受保护退化 |
| 仅预测到当前时刻 | 通过 | 通过 | 16 包存在受保护退化 |
| 延迟识别，不预测位置 | 未通过 | 通过 | 未进入候选验收 |
| 响应与延迟识别，不预测位置 | 通过，四方向穿越均为 0 | 通过 | 16 包存在受保护退化 |
| 联合状态估计、协方差估计 | 部分静止案例改善 | 现有专项回归失败 | 不具备验收资格 |

其中“响应与延迟识别、不预测位置”在旧浮点回执固定案例中把过冲降到约 0.5–1.04 px，但 `pure_standard / seed 1337 / ADS` 的获取目标数从 5 降到 4；其他序列也有跟踪或摆荡退化。这直接违反“不影响索敌/获取”的边界，所以相关代码已从生产目录撤回。实验源码和失败报告保留在运行目录，未把失败候选改名为修复。

这些结果支持把后续重构重点放在**模型误差与真实目标运动的区分，以及估计器和控制器使用一致的时间与单位**。它们尚不足以确定一个合格的新算法；继续统一降力度、延长滤波或放宽验收指标都不能替代这个问题。

## 保留修改的验证

- 10 个 Base/Feature suite、410 项测试全部通过，覆盖 ADS、BodyLock、人工权限、生命周期、AutoFire、recoil、输出和诊断。
- 16 个配对参数包、64 条序列、864 个固定目标机会：调用原有比较器，0 个参数包新增受保护退化。
- 在相同 DS4 解码回执模式下，开发种子 `20260926`、`8675309` 各 972 个随机长短案例，修复前后 JSON 逐项相同。扫描频率为 62.5–200 Hz，说明该范围行为保持一致，不能把它当作高频性能改善证据。
- 高频改善由前述 56 个确定性子案例证明；未见验证种子尚未消耗，因为广义摆荡候选还没有通过开发门禁。
- 本轮未新增左摇杆/跳蹲识别、原生输入防抖、后台 AI 更新频率或游戏专用补丁。

当前状态需要分别表述：高频观测回归已 RED→GREEN；整体摆荡优化仍是 **FAILED CONSTRAINTS**。随机模拟对真实 AA 的覆盖仍是 **EXPLORATORY / MISSING COVERAGE**。全套测试通过不代表固定失配事故已经修复。
